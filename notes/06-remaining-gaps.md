# 还缺什么：知识缺口 vs 数据缺口 vs 决策缺口

回答"还需要补哪些知识才能完善开发指导文档"。分三类，**因为三类的补法完全不同**：
知识缺口我能补（写文档），数据缺口只能靠标定/采集，决策缺口只能靠你拍板。

---

## 一、知识缺口（我能补，约 4 份文档）

### K-1 视口 LUT 的存储布局 —— 当前只有"要建 LUT"，没有"存成什么"

现有 `SPEC-COORD` §6 只说"Q12.4（int16，1/16 px）"，但没定义：

| 缺的 | 为什么重要 |
|---|---|
| 每个栅格点存哪些量 | 只存 `(u,v)` 还是也存有效性、深度系数？决定内存 4–16 字节/点 |
| 无效点的表示 | `(0,0)` 会和真实左上角像素混淆，必须用独立 mask 或哨兵 |
| Q12.4 溢出边界 | ±2048 px 覆盖得了 1920，但视口重排后坐标可能超出，要定义钳位还是标无效 |
| 非均匀栅格的组织 | `SPEC-EPIPOLAR` §3.3 说"每行有效宽度不同"，但没定是按行存偏移表还是稠密+mask |
| 双线性插值的跨界处理 | 四邻域里有无效点时怎么办（弃用该点？近邻？） |

**估算**：约 100 行，`SPEC-LUT.md`。

### K-2 时间同步与帧配对 —— 提到它重要，但没定义怎么判定和补救

`SPEC-CAMERA` 有"四路时间戳极差 ≤ 5 ms，否则整帧丢弃"，但缺：

| 缺的 | 为什么重要 |
|---|---|
| 单路内的帧间隔校验 | 20→15 Hz 瞬变时，基线计算会出错 |
| 时间戳来源与单调性检查 | 回绕、重复、跳变 |
| 位姿与图像的对齐方式 | 位姿时间戳在帧间隔中间时，插值还是取最近？ |
| 丢帧时的参考帧处理 | 参考帧来自 3 帧前（间隔翻倍），基线超限还是继续用 |

**估算**：约 120 行，并入 `SPEC-POSE.md` 或独立。

### K-3 下游输出协议 —— 只有 `NFPoint`，没有传输层

| 缺的 | 说明 |
|---|---|
| 序列化格式 | 字节序、对齐、版本、CRC |
| 共享内存/零拷贝的生命周期 | 谁分配、谁释放、写者与读者的同步原语 |
| 帧有效性标志的下传方式 | 冻结帧怎么告诉下游"这帧别用" |
| 时延预算 | 从图像采集到下游可读，允许多少 ms |

原 NFOCC 用 SERL + DataFrameServer，我的 docs **完全没写**（因为是他们的私有中间件）。
如果不复刻，需要你确认下游能接受什么格式。

**估算**：约 120 行，`SPEC-IO.md`。

### K-4 标定流程 —— 只在参数手册里列了"待标定"，没定义怎么标

| 缺的 | 说明 |
|---|---|
| KB 内参标定的输入/输出 | 用棋盘格还是标定场？多少个位姿？ |
| 四路外参的标定基准 | 相对何处（后轴中心？车身原点？），怎么保证四路一致 |
| 标定结果的验收指标 | 重投影误差 < ? px；**两路重叠区体素重合率**（见 `notes/00` §4） |
| 标定的有效期与再标定触发 | 温度、碰撞、换件 |

**估算**：约 150 行，`SPEC-CALIB.md`。

## 二、数据缺口（我补不了，必须先有）

| 编号 | 缺什么 | 挡住什么 | 最小可行替代 |
|---|---|---|---|
| D-1 | KB 内参 `f, cx, cy, k1..k4, r_valid` | 所有视差派生参数（`B_MIN`/`B_MAX`/`VF_VIEW`） | 用 `f=700, k=0` 跑 P0，但参数手册标注为估计值 |
| D-2 | 四路外参 | 视口朝向、地面覆盖、多相机汇聚 | 用典型环视布局（h=700、俯角 10°）跑 P0 |
| D-3 | 车身掩码位图 | `SPEC-MASK` 无法实际生效 | 合成场景里构造一个假车身多边形 |
| D-4 | 真实连续录像 + 位姿 + 真值 | P1 的 `σ_pixel` 实测、P2 的 150 mm 验收 | 全用合成数据，验收指标挂起 |
| D-5 | `σ_pixel` 实测值 | 精度预算的输入（`T_SIGMA_D`） | 默认 0.25 px，标注"未实测" |

**D-1/D-2 是硬阻塞**：没有它们，`PARAM.md` 的所有反推都是建立在 `f=700` 假设上的。
好在 P0 合成数据用同一套假设，自洽性验证不受影响——**但换成实车时参数要全部重算**。
`PARAM.md` 的 R2 关系已经写成自动断言，重算不会漏。

## 三、决策缺口（需要你拍板，每题给默认）

| 编号 | 问题 | 选项 | 我的默认 |
|---|---|---|---|
| X-1 | 视口降采样倍率 | 1（全分辨率，1.5 GB）/ **2（377 MB）** / 4（94 MB，精度差） | 2 |
| X-2 | 4 路并行还是串行 | 并行 1.93 GB / **串行 420 MB** | 串行 |
| X-3 | 下游协议 | 复刻 SERL / **自定义 + 适配层** / 双出 | 自定义 + 适配层 |
| X-4 | 引擎默认档 | **SGBM** / 模型 / 两者都编 | SGBM |
| X-5 | 单 Y 通道弱纹理处理 | **接受** / CLAHE / 加梯度通道 | 接受（实测后再定） |
| X-6 | 车身掩码类型 | **图像位图 368 KB** / 3D 凸多面体 | 图像位图 |
| X-7 | 是否需要自由空间（ray casting） | 需要 / **不需要，只出占用点云** | 不需要 |

X-7 值得展开一句：CMA 融合的是**点云质心**，无法表达"空"与"未知"的区别。
若下游需要可行驶空间推理（而不只是"这里有障碍"），必须在 CMA 之上叠加 ray casting，
那是另一个模块（`SPEC-FREESPACE`，目前没有）。**这取决于下游规划怎么用这套点云。**

## 五、结论：当前状态

| 维度 | 状态 |
|---|---|
| 链路能跑通的必需件 | **齐**（几何、引擎、三角化、位姿、体素、状态机、构建） |
| 点云质量的防御层 | **齐**（掩码、遮挡、FoE） |
| 工程骨架 | **齐**（`SPEC-BUILD`） |
| 每单元验收 | **齐**（`SPEC-VERIFY`，含负对照） |
| 存储与传输细节 | **缺**（K-1、K-3） |
| 标定流程 | **缺**（K-4） |
| 实车参数 | **缺**（D-1、D-2，硬阻塞实车） |

**能开始写代码了，能写出通过 P0 验收的工程。**
要交付到实车，还需要 K-1/K-3/K-4 三份文档 + D-1/D-2 两组标定数据。
