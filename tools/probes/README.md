# 探针清单 — 支撑 SPEC-FORWARD 与 PH1-ACCEPTANCE 的实测证据

所有探针都可直接跑，用于复核文档里的每个数字。
运行方式（仓库根目录）：

```bash
cd /Volumes/Workspace/NFOCC
PYTHONPATH=/Volumes/Workspace/NFOCC python3 tools/probes/<名字>.py
```

| 探针 | 回答什么问题 | 关键数字 |
|---|---|---|
| `probe_dir.py` | 前向平移时像移方向是否一致 | 左半 `du=+38.2px`，右半 `−38.2px` → **翻转** |
| `probe_dv.py` | 像移是否只有水平分量 | `\|dv\|/\|du\| = 0.23` → **是斜的** |
| `probe_yaw.py` | 不同平移方向下同一行极线是否平行 | 直行 **175.9°**；横移 90° 仍 **31.3°** |
| `probe_blocks.py` | 分块能否让块内极线收敛 | 横移 90°：120×32 块 **2.3°**；直行仍 5.7° |
| `probe_o2_real.py` | 前向解析测距在真实场景几何下是否无损 | 误差 **0.000 mm**，100% 像素 |
| `probe_product.py` | 产品管线五工况端到端 | FORWARD 247,680 点 / STEREO 53,456 点 |
| `probe_blockgain.py` | 分块接入后是否划算 | 视差 −31%，但覆盖率 −72%，深度仅 −5% |

---

## 关键结论的逻辑链（按探针顺序）

1. `probe_dir` + `probe_dv` + `probe_yaw` → **SGBM 在前向下结构性不可用**。
2. `probe_blocks` → 分块对前向也救不了（p90 仍 25°）。
3. `probe_o2_real` → **前向改用径向膨胀解析测距，方法本身无损**。
4. `probe_product` → 门控 + 两条路径串起来能出点云。
5. `probe_blockgain` → 分块对侧向也不划算，**默认关闭**。

第 3 点是本项目的关键转弯：从"想办法让匹配器工作"改为"换一个不需要匹配器的量"。

## 探针写作纪律（本项目踩过多次的教训）

1. **先怀疑探针，再怀疑实现**。本项目的 FAIL 里绝大多数是探针写错。
   已发生的：`Z` 用成光轴深度而非距离、噪声实验中判据函数没用扰动值、
   掩码含 `den>ε` 导致各档筛出不同子集、`dZ` 测试函数完全忽略入参。

2. **批量统计前先单点手算**。单点能对到 1e-16，批量出现 0.28 的相对误差时，
   一定是批量版和单点版在某个量上不一致，而不是"统计口径问题"。

3. **视口像素 ≠ 鱼眼像素**。`cam.unproject()` 吃鱼眼像素，`vp.pixel_to_ray()` 吃视口像素，
   混用会得到不闭合的结果（本项目实际踩过，往返误差 1402 mm）。

4. **确定性纹理**。合成数据里任何逐像素随机项都会破坏跨帧对应性，
   让匹配器"成功返回但全错"。纹理必须是 `f(x, y, z)`。

5. **噪声实验的掩码必须与噪声无关**。否则各噪声档筛出的子集不同，
   结果看起来"对噪声不敏感"，实际是统计不可比。
