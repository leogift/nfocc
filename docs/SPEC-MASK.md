# SPEC-MASK — 车身 ROI 掩码（源头剔除）

补齐审计缺口 **G-3**。本文档定义：车身掩码是什么坐标系下的什么数据结构、怎么标定、
在 LUT 的哪一步生效、以及它带来的副作用怎么处理。

上游依据：车身钣金、保险杠、外后视镜始终在鱼眼视野内（4 路环视的固有事实）。
不剔除的后果不是"精度略降"，而是**紧贴车身的一圈虚假静态障碍物**，
下游 APA 会把车判成"停不进去"。

---

## 1. 为什么必须在 LUT 阶段而不是体素阶段剔除

| 剔除位置 | 代价 | 副作用 |
|---|---|---|
| 体素阶段（体素落在车身多边形内则删） | 已完成三角化与融合，白算 | 无 |
| 视差阶段（车身像素置信度置 0） | 已完成匹配，白算 | 车身边缘像素污染邻域 |
| **LUT 阶段（射线穿过车身则标无效）** | **零计算** | 有效像素略减 |

LUT 阶段剔除的本质：**车身像素本来就不可能产生正确视差**（它是相机自己看到的自己，
不是一个物点），所以不必让它进任何计算。这是"从源头剔除"的确切含义。

**结论：在 `nf_lut_build` 内完成，不能放到下游。**

## 2. 数据结构

### 2.1 掩码的表示（三选一，必须显式声明）

```c
typedef enum {
    NF_MASK_NONE      = 0,   // 未标定, 全部有效(仅限调试, 禁止量产)
    NF_MASK_IMAGE     = 1,   // 原鱼眼像素空间: 1920x1536 的 1bit 位图
    NF_MASK_RAY_CONVEX= 2,   // 3D 凸多边形: 射线-多面体求交
} NFMaskKind;
```

| 类型 | 存储 | 判定方式 | 精度 | 推荐场景 |
|---|---|---|---|---|
| `NF_MASK_IMAGE` | 1920×1536/8 = **368 KB** | 查表 O(1) | 最高（逐像素） | **默认** |
| `NF_MASK_RAY_CONVEX` | 若干顶点 | 射线-凸体求交 | 中（近似车身外形） | 车身外形规则时 |

**默认用 `NF_MASK_IMAGE`**：368 KB 可接受，且逐像素精度天然吸收鱼眼边缘畸变；
凸多面体在鱼眼强畸变下与真实车身轮廓的贴合度不够，容易漏掉后视镜这类突出物。

### 2.2 结构体

```c
typedef struct {
    nf_u32 version;
    NFMaskKind kind;
    nf_u8  cam_id;
    /* kind == NF_MASK_IMAGE */
    const nf_u8 *bits;      // 1920*1536/8 字节, 行优先, bit=1 表示"车身"
    nf_u32 stride_bytes;
    nf_u32 dilate_px;       // 膨胀像素数 (PARAM: MASK_DILATE)
    /* kind == NF_MASK_RAY_CONVEX */
    nf_u32 n_verts;         // 顶点数
    const nf_f32 *verts;    // n_verts*3, V 系, mm
} NFCarBodyMask;
```

## 3. 生效点：LUT 构建流程中的位置

```
nf_lut_build:
  for each viewport pixel (up, vp):
     1. 视口射线 r (V 系)              ← SPEC-EPIPOLAR
     2. 按 pose 转到相机系, KB 反投影    ← SPEC-COORD 3.6-3.9
     3. 得到鱼眼像素 (uf, vf)
     4. 有效性检查:
        a. (uf,vf) 在图像内?           否 → valid=0
        b. r_d·f ≤ R_valid?            否 → valid=0   (NF_E_CAM_OUT_OF_VALID)
        c. **车身掩码命中?**            是 → valid=0   ← 本文档
        d. 射线是否落在有效视场内?      否 → valid=0
     5. 写 LUT: (uf, vf) + valid
```

**顺序不可调换**：掩码检查必须在 KB 反投影之后（需要像素坐标），
在写 LUT 之前（否则无效点已经进了表）。

## 4. 膨胀（必做，不是可选）

### 4.1 为什么必须膨胀

车身与背景的交界处存在**混合像素**（部分覆盖车身、部分覆盖背景）。在鱼眼边缘，
一个像素可能对应 0.3° 的视角，混合像素横跨远超 200 mm 体素对应的角度。
这些像素的视差是"车身与背景的加权"，三角化后落在车身附近的随机位置——
正是那圈虚假障碍物的主源。

### 4.2 膨胀量

`MASK_DILATE` 默认 **2 px**（`PARAM.md`）。依据：

| 膨胀 | 交界处混合像素覆盖 | 代价 |
|---|---|---|
| 0 | 完全暴露 | 环状伪点 |
| **2 px** | 覆盖典型混合带宽（约 0.2°） | 有效像素少 < 0.1% |
| 5 px | 过度 | 车身附近真实障碍物（如紧贴的柱子）被删 |

**2 px 是权衡结果，不是随手值**：`2 px × 0.099°/px ≈ 0.2°`，在 1 m 处对应 3.5 mm，
远小于 200 mm 体素；而实际混合带宽通常在 1–2 px。

### 4.3 膨胀必须在位图上做，不能在判定时做

正确：标定 → 膨胀 → 存盘 → 运行时只查表。
错误：运行时每次判定都做 5×5 邻域检查（慢 25 倍，且结果依赖遍历顺序）。

## 5. 与"车型标定"的绑定（换车型必须重标）

车身掩码是**车型相关的标定量**，不是相机内参的一部分。规则：

| 项 | 约束 |
|---|---|
| 版本字段 | 掩码必须带 `vehicle_model_id`，与 `PARAM.md` 的车型配置配对 |
| 换车 | 必须重新标定，**不得沿用** |
| 相机微调 | 车内参变化（如换镜头）也要重标，因为成像几何变了 |
| 缺失掩码 | `NF_MASK_NONE` 只能用于调试；量产配置必须拒绝启动（返回 `NF_E_PARAM_RANGE`） |

## 6. 掩码覆盖视场的量化（必须先算再实施）

掩码一旦生效，被掩掉的视场就永久不可用。必须先算清代价：

$$\text{view\_loss} = \frac{1}{W\cdot H}\sum_{u,v}\text{mask}[u,v] \tag{6.1}$$

经验范围：四路环视前/后相机的车身遮挡通常在视场下沿的 5–15%；
侧相机因为看到车门，可能更高。

**若某路相机 `view_loss > 30%`**：说明相机安装位置或朝向有问题（例如看到过多车门），
应在上游解决（挪相机/改朝向），而不是靠掩码硬删。这条要写进 `PHASE.md` 的验收。

---

## 7. 副作用与补救

| 副作用 | 说明 | 补救 |
|---|---|---|
| 车身最近的区域没有体素 | 掩码边界外的近场盲区（约 0.2–0.4 m） | 由该侧相机以外的其他相机覆盖，或接受 |
| 车身轮廓变化（开门） | 开门后新出现的车门仍在掩码内 | **无解**，需在下游标记该侧近场不可信 |
| 掩码与实车不符（换件） | 环状伪点重新出现 | 版本号 + 启动自检（见 §8） |

## 8. 验收

| 编号 | 级别 | 判据 | 负例（必须失败） |
|---|---|---|---|
| V-MASK-1 | L0 | 掩码位图尺寸 = 1920×1536，`stride_bytes` 自洽 | 传错尺寸 → `NF_E_PARAM_RANGE` |
| V-MASK-2 | L0 | 掩码内像素的 LUT `valid` 全为 0 | 去掉掩码判定 → 掩码内出现有效点 |
| V-MASK-3 | L0 | 膨胀后的掩码面积 ≥ 膨胀前，且差值为膨胀量决定的边界环 | 膨胀写成腐蚀（`erode`）→ 面积变小 |
| V-MASK-4 | L1 | 合成场景（车身为已知平面）下，车身像素产生的体素数 = 0 | 关闭掩码 → 出现环状伪点 |
| V-MASK-5 | L0 | `view_loss` 计算正确，且 > 30% 时告警 | — |
| V-MASK-6 | L0 | `NF_MASK_NONE` 在量产配置下被拒绝 | 允许启动 → 无剔除地跑 |

**V-MASK-4 是本规范的核心验收**：用合成数据构造一个"车身是平面"的场景，
关闭掩码时必然在车身位置产生一圈体素；打开后必须为 0。
这条能同时验证掩码方向、坐标系、生效点三件事。
