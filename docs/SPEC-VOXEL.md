# SPEC-VOXEL — 体素融合规范（Hash + CMA + 输出压缩）

补齐审计缺口 **G-1 / G-2 / G-9**。本文档定义体素从"一个 3D 观测点"变成"下游可读的点云柱"的
**全部算法**。离散化坐标见 `SPEC-COORD.md` §5，结构体见 `SPEC-ICD.md` §6。

---

## 1. 数据结构

```c
typedef struct {
    nf_i16 cx, cy, cz;   // 质心, 相对体素中心(mm), 范围 ±100 足够(体素 200mm)
    nf_u8  n_eff_x4;     // 有效观测数 ×4(置信度加权后可非整数), 饱和 255
    nf_u8  sigma_cm;     // 当前不确定度, cm, 饱和 255(超限哨兵)
    nf_u8  src_mask;     // bit0=FV bit1=RV bit2=ML bit3=MR
    nf_u8  flags;        // bit0=占用 bit1=已验证 bit2=冻结
} NFVoxel;               // 9 字节, 无填充
```

**质心存 `i16` 相对偏移而不是绝对坐标**：绝对坐标需要 24 位（±10000 mm），
存相对偏移只要 16 位，且体素尺寸固定 200 mm 时 ±100 mm 足够表示任何落在该体素内的点。
这把每体素从 12 字节+压到 9 字节。

## 2. 插入流程 `nf_voxel_insert`（唯一算法）

输入：一个 3D 观测点 `P`（V 系，mm）、`sigma_mm`（`SPEC-EPIPOLAR` 4.3 的 σ_Z）、
`conf`（0..1，来自引擎）、`src`（相机位）。

```
Step 1  索引: (ix,iy,iz) = floor 映射 (SPEC-COORD 5.1), 越界则丢弃
Step 2  哈希: h = (ix<<16)|(iy<<8)|iz
Step 3  查表: 开放寻址, 线性探测, 最大探测深度 HASH_PROBE_MAX
         找到占用体素 → Step 5 (融合)
         探测超限     → 丢弃该点, 计数上报, 返回 NF_E_VOXEL_FULL
Step 4  新体素: 质心偏移 = P − 体素中心, n_eff = 4·conf, sigma = sigma_mm/10, src_mask = 1<<src
Step 5  融合: 见 §3
```

### 2.1 为什么不按距离分摊到邻近体素

软指派（一个点按距离分给 8 个邻近体素）能减小"点落在体素边界时来回跳"的抖动，
代价是 **计算量 ×8 且每个体素都要算加权质心**，在 M57 上不划算。

**结论：硬指派，但用一个补偿措施** —— 见 §3.2 的"质心钳位"。这是本项目的取舍，不是遗漏。

## 3. CMA 更新式（这是 G-1 的核心，必须精确）

> **与本项目原 NFOCC 文档的对照**：原文档写
> $\bar{\mathbf p}_{n+1}=\bar{\mathbf p}_n+(\mathbf p_\text{new}-\bar{\mathbf p}_n)/(n+1)$，
> 即**等权整数计数**的累积移动平均。本规范采纳同一形式，但做了三处必要的扩展，
> 每处都有明确理由（见 3.1 / 3.3 / 3.2）。**核心的"增量拉向新值"这一思想不变。**

### 3.1 置信度加权累积平均（原文档已建议，本规范作为默认）

$$\mathbf{c}_{n} = \mathbf{c}_{n-1} + w\cdot\frac{\mathbf{p} - \mathbf{c}_{n-1}}{n_{\text{eff},n-1}+w},
\qquad n_{\text{eff},n} = n_{\text{eff},n-1} + w \tag{3.1}$$

其中：
- $\mathbf{p}$ 是本次观测点相对体素中心的偏移（mm，`i16` 存储前保留 float 中间量）
- $w = \text{conf}\cdot w_{occ}$（引擎置信度 × 遮挡权重，见 `SPEC-OCCLUSION` §4.3）
- $n_\text{eff}$ 是有效观测数（float 中间量，存 `n_eff_x4 = round(4·n_eff)`）

**当 `w=1` 时 (3.1) 退化为原文档的 `/(n+1)` 形式**，两者不矛盾。

**`w=0` 的观测必须直接跳过，不参与任何更新**（否则会以零权重污染质心）。

### 3.2 质心钳位（硬指派的补偿）

质心必须始终落在 `±vox_mm/2` 内：

$$c_i \leftarrow \operatorname{clamp}(c_i,\ -\text{vox}/2,\ +\text{vox}/2) \tag{3.2}$$

若不钳位，体素的质心会缓慢漂出自身边界（因为插入点一定在边界内，但累积平均在
体素"偏一侧被观测"时会偏向另一侧）。钳位代价极小，收益是相邻体素的质心不会互相穿越。

### 3.3 计数饱和与衰减

`n_eff` 上限 `N_EFF_MAX`（`PARAM.md::V_N_EFF_MAX`，默认 64）。达到上限后：

$$n_{\text{eff}} \leftarrow \alpha\, n_{\text{eff}},\quad
  \mathbf{c} \text{ 按 } (3.1) \text{ 用饱和后的 } n_{\text{eff}} \tag{3.3}$$

`α = 0.5`（等效"遗忘一半历史"）。**不饱和的后果**：跑久了 `n_eff` 极大，
新观测权重趋零，场景变化（比如车开走了）无法反映，体素会永久卡在旧位置。

### 3.4 不确定度的融合

按信息量融合（与 `SPEC-EPIPOLAR` 4.3 一致）：

$$\sigma^{-2}_{\text{new}} = \sigma^{-2}_{\text{old}} + \sigma^{-2}_{\text{obs}},
\qquad \sigma = \max(\sigma_{\min},\ \big(\sigma^{-2}_{\text{new}}\big)^{-1/2}) \tag{3.4}$$

`σ_min = 10 mm`（1 cm）：防止多次观测后 σ 趋零导致下游过度信任。

**不采用"取最小值"**：取最小会在一次低质量观测插进来时把 σ 永久压低，失去统计意义。

### 3.5 存在概率

$$p_\text{exist} = \min\left(100,\ \left\lfloor 100\cdot\frac{n_{\text{eff}}}{N_\text{eff}^{\text{sat}}}\right\rfloor\right),
\quad N_\text{eff}^{\text{sat}} = 8 \tag{3.5}$$

即"8 次等效观测后认为 100% 存在"。`SPEC-ICD` 的 `existence_prob` 就是它。

> 这是本项目的定义，**不是概率意义的贝叶斯后验**。若要真概率，需要空观测（ray casting）
> 做证据，那属于 `SPEC-FREESPACE`（尚未定义，见审计缺口）。

## 4. 输出压缩：zMap / zIndex（G-2 的完整构造流程）

### 4.1 唯一排序键

```
sort_key = (iy << 24) | (ix << 16) | iz          (4.1)
```

即**先按 Y、再按 X、最后按 Z**。下游寻址：

```
cell = ix * NY + iy            → 不是这个!
cell = iy * NX + ix            → 正确         (4.2)
```

**（4.2）是唯一允许的柱体编号方式**，与 `zindex` 的下标一一对应。
`SPEC-COORD` 里提到过 `HeightMapIdx = X_idx · W + Y_idx`（原文档写法），
本项目统一为 `iy*NX+ix`，**两者不能混用**（混用会导致图整体转置，而在方阵时无报错）。

### 4.2 构造步骤

```
Step 1  收集所有 flags.占用 的体素, 记录 (ix,iy,iz)
Step 2  按 (4.1) 的 sort_key 升序排序          → 得到 iz 在柱内递增
Step 3  zmap[cell] |= (1u << iz)  对每个体素    → 32 位位图
Step 4  point_buffer[] = 按排序顺序排列的 NFPoint
Step 5  zindex[cell] 从 0 起逐柱累加: zindex[c+1] = zindex[c] + count[c]
        (zindex 长度 = NX*NY + 1)
```

### 4.3 空柱体的表示

**用零长度表示**：`zindex[c] == zindex[c+1]`。**不用哨兵值**。
理由：哨兵会破坏前缀和的单调性，下游无法用统一公式寻址。

### 4.4 序号方向

`SPEC-COORD` §5.1 的 `iz` 是从 `Z_MIN` 起（下→上），所以 `zmap` 的 bit0 对应最低层。
**不要翻转**。若下游习惯"高处是高位"，在接口层转换，不在内部翻。

### 4.5 位宽与层数的关系（与原始文档对齐）

原始 NFOCC 文档描述 zMap 为"32 位整数，第 k 位表示第 k 层存在，可记录 31 层，
bit31 必须保留检查"。本项目**采纳 `uint32` 的约定，但层数由网格决定**：

| 项 | 原文档 | 本项目 | 说明 |
|---|---|---|---|
| 位宽 | 32 (`uint32`) | **32 (`uint32`)** | 一致 |
| 层数上限 | 31（bit0–30），bit31 保留 | **18（bit0–17）** | 由 `Z_MIN/MAX/`G_VOX`` 决定 |
| bit18–31 | 不适用 | **恒为 0，必须断言** | 留作将来扩展 Z 范围 |
| 有符号误用风险 | 有（`int32` 解读为负） | 同 | 统一 `uint32` |

**为什么本项目只需 18 层**：`Z ∈ [−1000, 2500]`（范围见 `PARAM.md` 的 `G_Z_MIN/MAX`）、体素边长取 `PARAM.md` 的 `G_VOX`
→ `3500/200 = 17.5` → 向上取整 18。
原文档的 31 层对应更大的 Z 范围或更小的体素，不适用于本项目。

**但"bit31 保留"这条纪律必须保留**：一旦将来扩展网格使 `nz` 增大，
若代码里 `zmap |= (1u << iz)` 且 `iz` 可为 31，就会置位符号位；
下游若按 `int32` 解读会得到负数。**V-VOX-3 的断言从 nz=18 起就生效**，
即使现在用不到 bit18，也要在写位时断言 `iz < 32` 且 `iz < nz`。

### 4.6 截断与 zindex 的关系

点数超 `MAX_POINTS` 时：

1. **不能直接砍尾部**——那会破坏 `zindex` 与 `zmap` 的一致性。
2. 正确做法：按柱体为单位，从"点数最多的柱体"开始整柱丢弃（或整柱标记为不可信），
   然后**重建** `zindex`。
3. 返回 `NF_E_OUTPUT_OVERFLOW`，下游据此知道有截断。

**这条是 V-VOX-5 的实质**：截断必须保持结构自洽，否则下游 O(1) 寻址会越界。

## 5. 哈希表实现约束（G-9）

| 项 | 值 | 依据 |
|---|---|---|
| 容量 | `NX·NY·NZ = 81000` 槽，**一次性全分配** | 81000 × 9 B = 729 KB，可全驻留，无需动态扩容 |
| 装载因子上限 | 0.7 | 超过则丢点并上报（不做 rehash，实时性优先） |
| 探测 | 线性探测，最大深度 `HASH_PROBE_MAX = 4` | 超过则丢弃该点（局部过密说明该区域体素已饱和） |
| 清空策略 | 每帧不清空，跨帧累积 | CMA 需要跨帧历史；重置见 `SPEC-BASELINE-SM` 的参考帧重置 |

**为什么不做 rehash**：动机会打乱已有质心位置，且会造成帧间延迟抖动。
81000 槽 × 0.7 = 56700 个有效体素，对 200 mm 网格的近场场景绰绰有余
（近场实际占用通常 < 5000）。

## 6. 验收

| 编号 | 级别 | 判据 | 负例（必须失败） |
|---|---|---|---|
| V-VOX-1 | L0 | `nz = 18`，末格半格被显式标记 | 用 17 → 顶部 200mm 丢失 |
| V-VOX-2 | L0 | 同一物理点连续插入 N 次，质心漂移 < 1 mm | `w=0` 的观测参与更新 → 漂移超限 |
| V-VOX-3 | L0 | `zmap` 为 `uint32`，nz=18 时 bit18+ 恒为 0 | 用 `int32` 且 `iz=31` → 负数 |
| V-VOX-4 | L0 | `zindex` 单调且 `zindex[NX*NY] == num_points` | 截断后不重建 → 不相等 |
| V-VOX-5 | L0 | 超限截断后 `zindex` 仍单调、`zmap` 与点缓冲一致 | 直接砍尾部 → 结构不自洽 |
| V-VOX-6 | L0 | **柱体编号 `iy*NX+ix`**：构造一个非方阵（NX≠NY）用例，检查 (3,5) 与 (5,3) 落到不同柱 | 用 `ix*NY+iy` → 两者互换 |
| V-VOX-7 | L0 | 质心恒在 `±vox/2` 内 | 去掉钳位 → 长序列后越界 |
| V-VOX-8 | L0 | `n_eff` 达到 `N_EFF_MAX` 后发生衰减 | 不饱和 → 新观测权重 < 1% |

**V-VOX-6 是新增的关键项**：NX=75 与 NY=60 不等（75≠60），这时两种编号方式**会不同**；
若测试只用方阵，写错了也测不出来。
