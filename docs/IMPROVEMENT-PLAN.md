# NFOCC 改进方案（2026-11-09）

依据三份材料：

- `docs/0_SKILL.txt`：参考量产系统的六个高级模块（柱面/圆锥视口、在线外参校准、3D 聚类与动静分割、引导滤波、Scratch Tile、ASIL-B/CRC/共享内存）。
- `harness/nfocc.json`：2026-11-01 那次长会话的交接记录，含已验证结论与被排除的假设。
- `docs/report/NFOCC-项目报告-2026-11.pdf` 与本次 11-09 复核。

结论先行：**当前瓶颈不是功能数量，而是"精度不可测"和"错误结论没人复核"。** 先把测量口径和已确认的正确性缺陷修好，再谈性能与 0_SKILL 的六个模块；否则会在错误的基线上调参。

## 2. 改进原则

1. **先可测，再正确，再快，再产品化。** 没有可信真值，任何精度"提升"都无法判断真假。
2. **每个修复必须有负对照。** 关掉修复应复现旧行为，否则不知道修复是否真的生效。
3. **不复制参考产品的参数。** 0_SKILL 的 `b_min=200 / b_max=460 / b_target=300` 对应 3.6–8.3 km/h；NFOCC 当前是 `278 / 833 / 500`，对应 5–15 km/h。直接照搬会把 15 km/h 工况砍掉。
4. **不动已验收的链路。** 默认门控、FORWARD 解算、体素融合、DVF 的既有测试必须继续绿。
5. **文档与代码同批交付。** 参数、状态码、测量口径改一处，同步 `docs/` 与报告。
6. **坐标约定固定。** 相机 OpenCV（x 右 / y 下 / z 前）；ego ISO 8855（X 前 / Y 左 / Z 上）。2026-11-09 确认：Y 右是左手系（前×右=下），不采用；若实车确实 Y 右，按 `SPEC-CONVENTION` §1.1 做全链路迁移。

## 3. 阶段计划

### P0 可测性与正确性（优先，1–2 周）

| 编号 | 任务 | 验收 | 依赖 |
|---|---|---|---|
| P0.1 | **精度测试协议重做**：前视用 590×1024 / 90°（f=295），侧视用 1024×475 / 150°；不再用一个全局 150° 视口测前向 | 同一场景分别跑前/侧，输出各段中位 + P95 + 样本数；能区分"视口口径"与"算法误差" | `NFPipelineConfig` 增加 `cam_mask` 或每相机视口参数 |
| P0.2 | **真值点云导出**：给测试输出点附带来源像素 (u,v) 与真值 Z；不再用"体素中心反投影"近似 | 1–5 m 每段 n≥500；与射线真值逐点对齐 | P0.1 |
| P0.3 | **地面以下点诊断**：`z < −100 mm` 计数、按来源相机拆分；先诊断不硬过滤 | 已落地：2,077 点中 236 点（11.4%），cam0 212 / cam1 24 / cam2 0 / cam3 0 | 无 |
| P0.4 | **D1 掩码文件化**：`--body-mask-dir` 读每路 PNG，缺失才回退矩形；负对照关掩码 | 车头覆盖、侧视不过挖；点数变化可解释 | 需要真实掩码或手工标注 |
| P0.5 | 双基线方向兜底 | 已完成：直行 `--baseline-mgr` 0→2,077 点；侧向仍 STEREO | — |

**P0.1 的关键判断**：现有 `test_depth_accuracy` 用 1024×475 / 150° 测所有相机，包括前向相机。前向设计视口是 590×1024 / 90°（f=295，视差是 150° 的 2.15 倍）。在错误的视口上测前向，得到的 291/256/433/896 不能直接判算法死刑。先把口径对齐，再决定是否改算法。

## 4. 与 0_SKILL 的逐项映射

| 0_SKILL 模块 | NFOCC 现状 | 差距 | 计划 |
|---|---|---|---|
| M1 柱面 / 圆锥视口 | 6 个平面针孔视口规划，主链 4 个 150° | 无柱面/圆锥；前向仍用侧视张角 | P3.1/P3.2 |
| M2 在线外参校准 | 无；外参静态 | 悬挂俯仰/打滑无补偿 | P3.3 |
| M3 3D 聚类 / 动静 | 网格哈希 + DBSCAN + 点级速度 + 簇投票 | 无柱状 CCL、无跨帧匈牙利、无 OBB | P3.4 |
| M4 引导滤波 / 散斑 | 仅 OpenCV SGBM 的 speckleWindow | 无保边滤波 | P2.1 |
| M5 Scratch Tile | 单一全局哈希；warp 并行、引擎串行 | 无局部缓存/无锁归约 | P2.4 |
| M6 ASIL-B / CRC / SHM | ZMQ 零拷贝；无 CRC/滚动/双缓冲 | 无端到端完整性 | P2.2/P2.3 |

**点结构差异**：0_SKILL 的 12 字节点含 `nRawPoints`；NFOCC 下游点是 10 字节，没有该字段。加字段必须升版本并同步下游，不能静默改布局。

**参数差异**：0_SKILL 的 `b_min=200 / b_max=460 / b_target=300` 是 3.6–8.3 km/h 包络；NFOCC 的 `278 / 833 / 500` 是 5–15 km/h。若产品要覆盖 3.6 km/h，应新增低速档并重算 `numDisp`，而不是全局改一个常量。

## 5. 本轮已落地（2026-11-09）

### 5.1 双基线方向兜底

`cpp/src/pipeline/pipeline.cpp`：状态机仍只按 `|t|` 判，但在把 `dec.mode` 交给相机前，按**该路视口**的 `σ=|t_xy|/|t|` 做兜底：

- `σ ≤ 0.35` 且状态机判 STEREO → 强制 FORWARD；
- 侧向视口 σ 接近 1，保持 STEREO。

结果：

```
修复前：--baseline-mgr 直行 → 46,821 次插入 / 0 点
修复后：--baseline-mgr 直行 → FORWARD，2,077 点（与默认门控一致）
```

### 5.2 测试夹具修正

`cpp/tests/integration/test_newmod_integration.cpp` 的 `make_rig()` 把 R 写成了转置（`R[col*3+row]`），cam0 一直因 `NF_E_EXTRINSIC_INVALID` 被禁用，状态机测试其实没测到 cam0。改为 `R[row*3+col]` 后，cam0 正常；新增 `pipe_baseline_manager_lateral_stays_stereo` 负对照，确保方向兜底不误伤侧向。

### 5.3 验证

```
ctest --test-dir build/host -E depth_accuracy   # 20/20
./build/host/tests/test_newmod_integration      # 4/4
./build/host/nfocc_run --hanqtech ../datasets/fisheye \
  --ws-frame 164 --frames 3 --stats --baseline-mgr   # 2,077 点
```

`depth_accuracy` 仍失败（预期，未动算法）；本轮不把它报成"已修复"。

### 5.4 地面以下点诊断（P0.3 第一步）

`nfocc_run` 增加 `BELOW_GROUND` 统计：真实帧 164 的 2,077 点中 **236 点（11.4%）** z<−100 mm，其中 cam0 212、cam1 24、cam2/3 为 0。问题集中在前向路径，侧向 SGBM 没有贡献。这比"全体点云有负 z"更能定位：下一步查前向径向匹配的对应点与地面交点。

### 5.5 报告修正

`z = −498 mm` 之前被解释为"点在相机后方"，这是坐标系误读：z 是 ISO 8855 高度，−498 mm 是地面以下。`nf_triangulate_rays` 已拒绝 `s≤0`，所以它不是负深度射线。报告已改为"地面以下点"，并明确先诊断、不硬过滤。

## 6. 下一步（按顺序）

1. **P0.1 + P0.2**：先做前视 90°/侧视 150° 的分视口精度测试，并导出带来源像素的真值点。判定"291/256/433/896"里有多少是视口口径、多少是算法误差。
2. **P0.3**：地面以下点按来源相机/视差段拆分；若集中在某一路，先查该路的视口/外参/视差范围。
3. **P0.4**：D1 掩码文件化，用真实掩码替代矩形占位。
4. P1 性能、P2 生产化、P3 几何，按上表推进。

在 P0.1 完成前，不建议动 SGBM 参数或加滤波——那是在没有可信测量的基线上调参。
