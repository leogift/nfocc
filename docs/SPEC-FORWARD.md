# SPEC-FORWARD — 前向运动的径向膨胀测距

**为什么需要这份规范**：PH-1 实测证明，纯前向（沿光轴）平移时，
"按行单向搜索"的立体匹配器（SGBM 及其同族）**结构上不可用**，
调参无效。前向又是最常见的工况，不能放弃。本规范给出正确的算法。

---

## 1. 问题的定性（三条实测事实）

| 代号 | 事实 | 探针 | 数字 |
|---|---|---|---|
| A | 像移方向**左右翻转** | `out/probe_dir.py` | 左半 `du=+38.2px`，右半 `−38.2px` |
| B | 像移**不只是水平** | `out/probe_dv.py` | `\|dv\|/\|du\| = 0.23` |
| C | 同一行**极线不平行** | `out/probe_yaw.py` | 行内离散 **175.9°** |

C 的根因：视口环带跨俯角 10–60°，有效基线差 2 倍（`cos10°=0.98` vs `cos60°=0.50`），
所以不存在能把所有极线转成水平的单一旋转。**分块也救不了**：60×16 分块后 p90 仍 25°。

---

## 2. 正确关系（推导）

物点 `P` 固定，相机 `c₀ → c₁ = c₀ + t`：

$$\mathbf{q}_0 = P - c_0 = Z\,\hat{\mathbf{u}},
  \qquad Z = |\mathbf{q}_0| \quad\text{(距离, 不是光轴深度)}$$

$$\mathbf{q}_1 = P - c_1 = \mathbf{q}_0 - \mathbf{t}$$

当前帧观测方向 `v̂` 与 `q₁` 同向，故三向量共面：

$$\mathbf{q}_1 \times \hat{\mathbf{v}} = 0
  \;\Longrightarrow\;
  Z\,(\hat{\mathbf{u}} \times \hat{\mathbf{v}}) = \mathbf{t} \times \hat{\mathbf{v}}$$

最小二乘解：

$$\boxed{Z = \frac{\sum \big[(\hat{\mathbf{u}}_i \times \hat{\mathbf{v}}_i)\cdot(\mathbf{t}\times\hat{\mathbf{v}}_i)\big]}
                     {\sum \big|\hat{\mathbf{u}}_i \times \hat{\mathbf{v}}_i\big|^2}} \tag{2.1}$$

**这个式子对任意平移方向成立**，不要求极线平行，不要求单向搜索。

### 2.1 三个已踩过的坑（写进规范，防止重犯）

| 坑 | 现象 | 根因 |
|---|---|---|
| **F-1** | 解出 393，真值 921 | `Z` 混用"距离 `\|q₀\|`"与"光轴深度 `q₀.z`"。**(2.1) 里 `Z` 必须是距离** |
| **F-2** | 系统偏差 194 mm | 输入用**像素**而非**方向向量**。视口的 `v` 定义成"相对环带中轴的仰角"，与标准针孔 `f·y/z` 差 **208 px**（实测） |
| **F-3** | 结果恒定不随噪声变化 | 判据函数没用扰动值；掩码含 `den>ε` 导致各档筛出不同子集，统计不可比 |

**因此 API 强制接收方向向量**，见 `nfocc_ph1/forward_range.py::forward_range_from_rays`。

## 3. 精度

解析式本身无损（自校验 `7.8e-15`）。误差**全部**来自对应点（`v̂`）的测量精度：

| 对应点精度 | 深度误差中位 | p90 | 相对 200 mm 体素 |
|---|---|---|---|
| 1.0 px | **110 mm** | 457 mm | 勉强 |
| 0.5 px | **55 mm** | 232 mm | **满足** |

灵敏度严格线性（`0.5px/1px = 0.49`）。

> **工程结论**：对应点必须做到 **≤0.5 px**（亚像素）。这直接决定了下一阶段
> （光流/特征匹配）的指标，不能放松。

---

## 4. 冻结与门控

不按"直行/转弯"这类工况标签决策，而按**平移方向相对光轴的角度**：

$$\sigma = \frac{|\mathbf{t}_{\perp}|}{|\mathbf{t}|},
  \quad \mathbf{t}_\perp = (t_x, t_y) \tag{4.1}$$

| 条件 | 模式 | 说明 |
|---|---|---|
| `frame_gap > GAP_MAX` | `FROZEN_GAP` | 丢帧，基线与位姿不可信 |
| `B < B_MIN` | `FROZEN_NEAR` | 基线不足 |
| `B > B_MAX` | `FROZEN_FAR` | 基线过大，重投影误差超限 |
| `σ ≥ SIGMA_STEREO_MIN`（0.80） | `STEREO` | 侧向，极线接近水平 |
| `σ ≤ SIGMA_FORWARD_MAX`（0.35） | `FORWARD` | 前向，走 (2.1) |
| 中间 | `HYBRID` | 两条路都跑，按置信度融合 |

实现：`nfocc_ph1/gating.py::decide`。

**冻结时不产出点云**（`points is None`），不是产出空点云 ——
下游必须能区分"这帧没结果"与"这帧确实没障碍物"。

## 5. 侧向的立体路径

侧向（`σ≈1`）仍走 SGBM，但有两条硬约束：

### 5.1 配对方向由 `t_cam.x` 的符号决定

SGBM 假定 `right(x) = left(x−d)`，`d≥0`。实测侧移 120 mm 时 `du` 中位 **−85.8 px**，
直接喂进去 SGBM 只输出 **4.4 px**（看似成功，实则全错）。

**规范**：
```
t_cam.x < 0  ->  u₂ = u + d
t_cam.x > 0  ->  u₂ = u − d
```
方向写反会导致三角化 100% 得到负深度 —— 已做成负对照 `N-4`。

### 5.2 纹理必须是 3D 点的确定性函数

合成数据里若用逐像素随机噪声，同一物点在两帧灰度不同（实测 192 vs 196），
SGBM 输出与真值完全不相关（真值 133 px，输出 3.6 px）。
**仿真器要求**：纹理 = `f(x, y, z)`，无随机项。见 `nfocc_ph1/product.py::deterministic_texture`。

### 5.3 已知残余误差与分块实测结论

侧向整幅匹配仍有 9–77 px 误差（极线不平行所致）。
分块剪切校正（`nfocc_ph1/blockmatch.py`）已实现并实测，**结论是不划算，默认关闭**：

| 方法 | 有效比例 | 视差误差中位 | 深度误差中位 |
|---|---|---|---|
| 整幅 | **21.6%** | 27.4 px | 649 mm |
| 分块 480×128（6 块） | 12.7% | 21.8 px | 804 mm |
| 分块 320×64（15 块） | **6.0%** | **18.8 px** | 619 mm |

视差误差降 31%，但覆盖率掉 72%，深度误差只改善 5%。三个原因：

1. **块宽必须 > `numDisparities`（256）**，否则 OpenCV 分配 `(W−numDisp)×H` 的负尺寸内存，
   报 `Insufficient memory` 而非参数错误（实测 60×16 块配 256 档直接 OOM）。
   这使最小块 320 宽 = 每行仅 3 块，分块粒度受限。
2. 剪切在块左右各削掉 `cut` 列，多块累积损失大量边界像素。
3. 深度误差主项是 `Z²σ_d/(f·b)`，27 px 视差误差在 B=120 mm 下本就对应 600 mm 量级，
   降 8 px 只换来 30 mm。

**规范**：`use_blocks` 默认 `False`。代码保留，供后续改变块大小策略时复用。
若将来要重启分块，前提是先解决"块宽 > numDisp"的约束（例如把前向/侧向的视差容量分开设定）。
