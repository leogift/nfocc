# SPEC-P0-SYNTH — P0 合成数据生成器规范

P0 阶段没有实车数据，所有验收都跑在合成数据上。合成数据的**可信度决定验收的可信度**——
本项目已经出现过"探针自己错、结论被当真"的情况，所以生成器本身必须有自检。

---

## 1. 要生成什么

单场景 = 一帧四路图像 + 前后两帧位姿 + 逐像素真值。产物全部落盘，可重放。

| 产物 | 内容 | 用途 |
|---|---|---|
| `cam_<id>_y.raw` | 1920×1536 单 Y，8 bit | 引擎输入 |
| `cam_<id>_valid.bin` | 1920×1536 1 bit（打包 uint8） | 有效区掩码 |
| `pose_<k>.json` | `R_cv`、`t`、时间戳 | 基线状态机输入 |
| `gt_disp_<cam>_<k>.raw` | float32，视口坐标系下的真值视差 | 引擎验收（V-ENG-3） |
| `gt_depth_<cam>_<k>.raw` | float32，米 | 三角化验收 |
| `scene.json` | 场景参数（几何体、材质、内参、外参） | 可复现 |

### 1.1 相机与内参

按 `PARAM.md`：
- 内参取 `PARAM.md` 的 `INF_*` 默认值（**不在此处复制数值**，避免两处漂移）
- 外参按 `SPEC-CALIB-CFG` §1 的定案值（h=700 mm、俯角 0°、四路 yaw 0/180/90/−90），
  由 `tools/calib_gen.py` 生成 `scene.json`，**不在本文硬写数值**

### 1.2 场景内容（覆盖验收需要的几类）

| 场景 ID | 内容 | 验什么 |
|---|---|---|
| `S_FLAT` | 单一地面平面，纹理为随机斑块 | 基本几何链、V-CO-2 |
| `S_BOX` | 地面 + 1 个已知尺寸的立方体障碍 | 三角化精度、V-CO-5 |
| `S_EDGE` | 地面 + 竖直平面（墙） | 视差不连续、引擎边缘 |
| `S_WEAK` | 地面无纹理（纯渐变） | 弱纹理下的有效率 |
| `S_MULTI` | 三个不同距离的立方体（0.5 / 2 / 5 m） | 视差动态范围 10:1 |

## 2. 渲染方式（必须与内参模型一致）

**关键：合成必须走与真实系统完全相同的成像链路，否则合成数据验收不到真实缺陷。**

```
1. 在 V 系定义几何体（解析的平面/立方体，不引入网格模型）
2. 对鱼眼图像的每个像素 (u,v)：
     a. 用 KB 反投影（SPEC-COORD 3.6–3.9）得到 V 系单位射线 r
     b. 与几何体求交，得距离 t 与交点 P
     c. 若 t 对应 r_d·f > R_valid → 该像素无效（写 0，valid=0）
     d. 按交点所在面的材质/纹理采样灰度
3. 输出单 Y 通道 8 bit
```

**禁止**用"先渲染针孔图再 warp 成鱼眼"的两段式——第二段重采样会掩盖 LUT 与反投影的错误。

### 2.1 纹理

用确定性噪声 + 低频斑块（`seeded`），保证两次运行逐位一致（V-ENG-2 需要）。
**不要用真实照片**：真实纹理带未知畸变与噪声，无法做真值。

---

## 3. 真值视差的定义（最容易搞错的地方）

对给定参考帧 `k` 与当前帧 `k+1`，在**视口坐标系**下：

```
1. 视口像素 (u_P, v_P) → 视口射线 → V 系射线 r
2. 与几何体求交 → P_ref
3. 把 P_ref 用当前帧位姿投影到当前帧视口 → (u_P', v_P')
4. 真值视差 d_gt = u_P − u_P'
```

- 若第 3 步落到视口外或无效区，该像素的真值标为**无效**（不参与统计）。
- **同一批点、同一批位姿**生成 `gt_disp` 与图像，否则会出现"真值和图像错位"的假 FAIL。

### 3.1 视差符号必须与实现一致

`SPEC-COORD` §4.2 定义 `d = u₁ − u₂ > 0`（相机向右移动）。生成器必须按同一定义写 `gt_disp`。
**生成器与实现各写一套符号，是最常见的假验收来源。**

## 4. 位姿轨迹

| 轨迹 ID | 描述 | 用途 |
|---|---|---|
| `T_STATIC` | 完全静止 | V-BS-1 |
| `T_ROT` | 原地旋转，`b≈0`，`ω=20°/s` | V-BS-2 |
| `T_LINE` | 直线 0.5 m/s 加速 | V-BS-3 |
| `T_OVER` | 直线 2 m/s，覆盖到 `b>B_MAX` | V-BS-4 |
| `T_TURN45` | 边走边转，运动方向 45° | V-EPI-3 / V-EPI-4 |

轨迹以 50 ms 为步长（`B_LAT_MAX` 的依据）。

## 5. 生成器自身的验收（必做）

| 编号 | 判据 | 方法 |
|---|---|---|
| V-SYN-1 | 同一场景两次生成，文件逐字节相同 | `sha256` 比对 |
| V-SYN-2 | **把真值视差代回三角化公式**，得深度的相对误差 < 1e-6 | 解析可算 |
| V-SYN-3 | **把真值视差按 1/16 px 量化后**，代入三角化，误差与 `SPEC-EPIPOLAR` (4.3) 的 `σ_Z` 同量级 | 数值验证 |
| V-SYN-4 | 图像与真值同批生成：从图像上取一个已知角点，其视差与 `gt_disp` 一致（< 0.5 px） | 抽查 |
| V-SYN-5 | `R_valid=768` 之外真值全标无效 | 边界统计 |

**V-SYN-3 是最有信息量的一条**：它同时验证生成器、三角化公式、量化模型三者一致。
若这条通过而 V-ENG-3 不过，问题一定在引擎。

---

## 6. 与后续实车数据的替换性

生成器输出 `scene.json` 描述"这台合成的车"的内外参。
换成实车数据时，只需把 `scene.json` 替换为真实标定文件，
**下游代码不改任何一行**——这是检验"数据接口设计是否正确"的标准。

若换数据需要改代码，说明合成的数据布局把假设写死了，必须回头改。

## 7. 目录布局

```
data/synth/
  <scene_id>/
    scene.json
    cam_FV_y.raw  cam_FV_valid.bin
    cam_RV_y.raw  ...
    pose_000.json pose_001.json
    gt_disp_FV_000.raw
    gt_depth_FV_000.raw
```

`scene.json` 字段（唯一 schema，其他工具不得自造）：

```json
{
  "version": 1,
  "image": {"w": 1920, "h": 1536, "dtype": "uint8", "channels": 1},
  "cameras": [
    {"id": "FV",
     "intr": {"f": 700.0, "cx": 960.0, "cy": 768.0, "k": [0,0,0,0], "r_valid": 768.0},
     "extr": {"R": [9 floats], "t": [3 floats]}}
  ],
  "frame": {"dt_ms": 50},
  "geometry": [{"type": "plane", "normal": [0,0,1], "d": 0, "material": "ground"}]
}
```

## 8. 交付判据

P0 结束时必须能执行：

```
python tools/synth_gen.py --scene S_MULTI --traj T_LINE --out data/synth/S_MULTI
python tools/synth_selfcheck.py --dir data/synth/S_MULTI      # V-SYN-1..5
```

两条命令的输出为 PASS/FAIL 集合，**且每个 PASS 都要有对应的负例在 `--inject-fault` 下变 FAIL**。
