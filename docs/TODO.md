## TODO-1 车身 mask 应该由相机视图直接提供，而不是几何投影推算

**记录时间**：2026-11-02
**优先级**：高（阻塞点数产出与精度验证）
**来源**：用户观察「车身mask很奇怪，应该提供相机视图的mask来处理」

### 问题

当前的 D1 车身掩码是**几何推算**出来的：把车体俯视矩形（5000×2000）逐顶点
投影到每路原图，再光栅化成像素掩码（`nf_mask_build_vehicle` →
`nf_mask_rasterize_polygon`）。

实测覆盖率（hanqtech 帧 164）：

| 相机 | 覆盖像素 | 占比 |
|---|---|---|
| cam0 (FV) | 1689 | **0.1%** |
| cam1 (RV) | 282835 | 22.9% |
| cam2 (MVL) | 947738 | **76.6%** |
| cam3 (MVR) | 955239 | **77.3%** |

开启后点数从 661 掉到 195（-70%）。

### 为什么"很奇怪"

**MVL/MVR 覆盖 76%+ 意味着侧视相机四分之三的画面被当成车身挖掉了。**
这正是把 3D 矩形投影到贴车身安装的鱼眼上的必然后果：

1. 相机贴在车身边上（侧视相机 y = ±1000mm，正好在矩形边界上）
2. 光轴下俯 74°，视野大半朝下，看到的就是车身侧面
3. 矩形是**凸的、没有轮廓细节**，会把后视镜、轮眉、车门凹槽之外
   本不属于车身的区域也框进去

前视 cam0 只有 0.1% 则是另一个极端——车头在视野底部之外，矩形几乎不投影
到画面上。**同一个矩形在四个相机上表现差异如此之大，说明这个建模方式本身
不成立**，不是参数没调好。

### 正确做法：由标定数据直接提供每路相机视图的 mask

车身遮挡在**相机成像平面**上是固定的——只要相机相对车身不动，这层遮挡就
不变。所以它应该是**标定产物**，不是运行时几何计算：

- 在标定阶段（或一次性离线）对每路相机采集一帧"空场景"，用
  **真实车身轮廓**（不是矩形）标注出遮挡区域，存成每路一张
  `mask_<cam>.png`（原图分辨率，1 字节/像素）
- 运行时直接加载，`nf_lut_build` 里按原图像素索引查表即可，不做投影

好处：
1. 能表达任意轮廓（后视镜、轮眉、保险杠弧线），不需要用凸多边形近似
2. 运行时零计算（现在每路要做 64 段细分的多边形投影 + 光栅化）
3. 与相机外参解耦——外参漂移不影响掩码本身的有效性
4. 可人工修正：标定后肉眼看一眼掩码对不对，直接改

### 需要的外部支持

| 项 | 说明 | 没有时怎么办 |
|---|---|---|
| 每路相机的车身遮挡标注图 | 真实轮廓，原图分辨率，二值 | 用现有矩形投影兜底，但要接受 70% 的点被误删 |
| 车体俯视轮廓多边形 | 若坚持用投影法，至少给真实多边形而非矩形 | 同上 |

### 实现要点（拿到数据后）

1. 新增 `nf_mask_load(path, w, h, out_mask)` 读 PNG（io 层，不进核心库）
2. `NFPipelineConfig.body_mask[c]` 已是每相机独立指针，接口不用改
3. `nf_mask_build_vehicle` 保留为**兜底**（无标注数据时用），在文档里标明
4. 掩码尺寸必须与原图一致——注意之前踩过的坑：`nf_lut_build` 里曾硬编
   1920×1536 而实际图像是 1280×966，导致行 stride 全错、掩码整体错位

### 验收判据

- [ ] 每路掩码的覆盖像素数与该相机实际被车身遮挡的面积相符（人工核对）
- [ ] 开启 D1 后点数下降幅度合理（预期 10-20%，不是现在的 70%）
- [ ] 关闭 D1 后点数回升（负对照仍成立）
- [ ] 掩码图能可视化输出（`viz/06_body_mask`）供人工检查

## TODO-2 修 depth_accuracy：给合成场景加随机相位纹理

**优先级**：高
**影响**：决定 150mm@5m 目标能否成立，也是聚类有无实用价值的前提

`test_depth_accuracy` 失败，实测视差误差 14–42 px（判据 0.6 px）。根因是
合成场景只有地面 + 一面墙，纹理是规则周期函数，SGBM 锁错周期——墙面理论
视差 140.8 px 时给出 2.2 px。

这是**场景缺陷不是算法能力**。加随机相位扰动后重跑探针，得到的才是 SGBM
在"有纹理可匹配"条件下的真实亚像素精度。
