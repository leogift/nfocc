### 1.1 序号不是同步 ID

**每路相机独立递增**，不是四路共用一个 timestamp 序号：

```
00164_FV  00165_MVL  00166_MVR  00167_RV
00168_FV  00169_MVL  00170_MVR  00171_RV
```

即 `frame_id` 传 **FV 的序号**，其余三路为 `+1/+2/+3`（按 FV/MVL/MVR/RV 顺序）。

**踩坑记录**：第一版四路都用同一个 `frame_id`，结果只有 FV 加载成功，
其余三路的 `nf_ws_load_calib` 全部失败，程序却继续往下跑。

## 2. 内参：四次多项式 ρ(θ)

```
ρ(θ) = k1·θ + k2·θ² + k3·θ³ + k4·θ⁴

χ  = √(X² + Y²)
θ  = atan2(χ, Z)
u' = ρ·X/χ                       (χ=0 时为 0)
v' = ρ·Y/χ
u  = u' + cx_offset + width/2 − 0.5
v  = v'·aspect_ratio + cy_offset + height/2 − 0.5
```

### 2.1 与 KB 模型的区别（关键）

| | KB（项目理想基线） | RADIAL_POLY（hanqtech） |
|---|---|---|
| 形式 | `r = f·[θ + k1θ³ + k2θ⁵ + …]` | `ρ = k1θ + k2θ² + k3θ³ + k4θ⁴` |
| 项次 | 只有奇次 | **含偶次** |
| 焦距 | 单独给 `f` | **k1 就是焦距**（px/rad） |

**不能套用同一组系数**。hanqtech FV 的 `k1=339.75` 是焦距，
若当 KB 的畸变系数用，θ>0.2 rad 处投影完全失真。

代码：`NFCameraModelKind`（`NF_CAM_MODEL_KB` / `NF_CAM_MODEL_RADIAL_POLY`）。
内部用 `model_scale()` 统一两者：`r_pixel = K · theta_d_normalized(θ)`，
KB 时 `K=f`，RADIAL_POLY 时 `K=k1`。

### 2.2 主点不等于 cx_offset

`cx_offset` 只有 3.9 px 量级，**不是主点像素坐标**。真正的主点是：

```
cx = cx_offset + width/2 − 0.5
```

实测四路：

| 相机 | cx_offset | 实际主点 cx | 图像中心 |
|---|---|---|---|
| FV | 3.942 | 643.44 | 640.0 |
| MVL | 1.829 | 641.33 | 640.0 |
| MVR | 3.468 | 642.97 | 640.0 |
| RV | 6.670 | 646.17 | 640.0 |

### 2.3 视场

四角 θ ≈ **112°**，ρ 多项式在 [0, 120°] 上单调。`max_theta` 取 120°。

## 3. 外参：与项目约定完全一致

readme 明示：camera → vehicle 的变换，四元数用 `Rotation.from_quat`（xyzw）。

实测三条全过：

| 项 | 结果 |
|---|---|
| `det(R)` | +1.000000 |
| `‖RRᵀ − I‖` | < 1e-6 |
| 相机 y 轴在车系 z 分量 | 四路均为负（朝下） |
| 光轴与径向夹角 cos | +0.126 ~ +0.923（朝外） |

**结论**：`NFPose.R = M`（行优先展平）、`NFPose.t = translation × 1000`（mm），
无需任何坐标变换。

### 3.1 真实安装角（与理想外参差别很大）

| 相机 | 光心 (mm) | 方位角 | **俯角** |
|---|---|---|---|

| MVL | (1945, +957, 955) | +105.9° | **73.8°** |
| MVR | (1945, −957, 975) | −107.9° | **74.2°** |

## 4. 环带语义：绝对俯角（本节的结论改了一处既有实现）

视口环带 `EL_MIN=10°, EL_MAX=60°` 的含义**必须是绝对俯角（相对地面）**，
而不是相对光轴。

### 4.1 为什么

早期实现把环带角当"相对光轴"，在理想外参（俯角 0°）下恰好成立。
接入真实外参后完全失效：

| 解释 | FV 实际视口俯角 | 看到的地面距离 |
|---|---|---|
| 相对光轴 | 22.7 + 35 = **57.7°** | **432 mm**（车头正下方） |
| 绝对俯角 | **35.0°** | **973 mm** |

两种解释在真实 FV 图像上的投影点分布原先见 ring_semantics_check.png（当前树未提供）：
红点（相对光轴）挤在画面下沿，绿点（绝对俯角）分布在中下部路面。

### 4.2 实现

```
视口像素 -> 视口系射线 rp（俯角 = 绝对俯角）
        -> 车系:  rw = R · rp
        -> 相机系: rc = Rᵀ · rw
        -> 鱼眼投影
```

`view_lut.cpp` 里不能直接把 `rp` 当相机系方向用。

## 5. 视口尺寸由规划表决定，不再按原图宽推导

6 视口模式（`--sfm6`）的尺寸来自 `NFViewPlanEntry.width_px` + `hfov/vfov`，
与 `downscale` 无关；`f = (W/2)/tan(hfov/2)`。

| 视口 | 尺寸 | 张角 | f |
|---|---|---|---|
| FV/RV ±45/±135 | 590×716 | 110° | 206.6 |
| ML/MR ±90 | 1024×475 | 150° | 137.2 |

旧 4 视口模式仍用 `cfg.view`（1024×475/150°）。历史上曾按“图像宽/downscale”
推导出 960×258 或 640×172，这把“原图分辨率”和“视口设计”绑死；现在两者解耦：
视口是设计参数，原图只决定 LUT 能采到多少有效像素。

## 6. 位移从哪来

`vehicle_info/*.json` 字段：`speed / yawRate / steering / acceleration / distance / gear`。
**没有位姿**。

当前做法（`ws_source.cpp`）——**投影到视口系，不是相机系**：

```
move_mm = ego_distance(m) × 1000 × (gear == 'R' ? -1 : +1)
车体位移 t_V = (move_mm, 0, 0)                行驶方向 = 车体 +X
投影到该路视口系（SPEC-CONVENTION §2 的基向量）：
  视口 forward = (cos yaw, sin yaw, 0) = 视口 z
  视口 right   = (sin yaw,-cos yaw, 0) = 视口 x
  t_cam[0] = move_mm · sin(yaw)      <- 视口 x
  t_cam[1] = 0
  t_cam[2] = move_mm · cos(yaw)      <- 视口 z
```

> **2026-11 修正**：此前写成 `t_cam[0] = move·cos(yaw)`、`t_cam[2] = 0`，
> 把前进位移放到了视口**横向**。yaw=0 时前向分量为 0 —— 基线为零，
> 且门控按"有横向位移"误判成 STEREO 走 SGBM（掩盖了 FORWARD 分支的
> 性能问题）。实测症状：点云出现负深度 -497mm、水平距全在车外
> 3.6-8.9m、插入 16169 点最后只剩 55 个。修正后点数 55 -> 2077。

**局限**：忽略横摆。三组数据的 `yawRate` 分别为 0.43 / 0.00 / 1.95，
按纯纵向处理在转弯段（1.95）会有偏差。若要用于真实评测，
应由 `yawRate × dt` 补上横摆，或改用上游提供的位姿。

```bash

nfocc_run --hanqtech <datasets/fisheye> --ws-frame 164 --frames 3 --stats --sfm6
```

2026-11-19，帧 164：

| 项 | 6 视口 | 4 视口 |
|---|---:|---:|
| 融合后点云 | **2,019 点** | 1,999 点 |
| 有效帧 | **104.6 ms** | 179.4 ms |
| 水平距均值 | **5,009 mm** | 5,854 mm |
| z < −100 mm | 233（11.5%） | 247（12.4%） |
| RSS | 165.3 MB | 123.3 MB |

`z` 最小值约 −498 mm 是 **ISO 8855 高度**（地面以下），不是“点在相机后方”。
`nf_triangulate_rays` 已拒绝 s≤0；这个负值是错误视差/射线组合解出的地下点，
不是负深度。地面以下点仍占 11.5%，见 `IMPROVEMENT-PLAN.md` P2。

### 历史性能记录（4 视口，旧代码）

旧 `nf_match_radial` 逐像素标量循环，未降采样/并行：3429 ms/帧（FORWARD），
STEREO 35 ms；这是 2026-11-09 之前的基线。P1 的快速匹配把 4 视口降到 191.8 ms，
6 视口默认 104.6 ms；`--forward-full` 仍保留全质量路径作对照。

### 已知限制

- 真实数据没有点云真值（只有 ego_distance/ego_yawRate），只能验证链路与
  几何范围，不能验证绝对精度。
- 忽略横摆：三组 yawRate 0.43/0.00/1.95，按纯纵向处理在 1.95 转弯段有偏差。
- 6 视口 RV 两路在帧 164 只出 27/188 个插入点（后向弱纹理），覆盖贡献小。
