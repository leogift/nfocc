### 1.1 序号不是同步 ID

**每路相机独立递增**，不是四路共用一个 timestamp 序号：

```
00164_FV  00165_MVL  00166_MVR  00167_RV
00168_FV  00169_MVL  00170_MVR  00171_RV
```

即 `frame_id` 传 **FV 的序号**，其余三路为 `+1/+2/+3`（按 FV/MVL/MVR/RV 顺序）。

**踩坑记录**：第一版四路都用同一个 `frame_id`，结果只有 FV 加载成功，
其余三路的 `nf_ws_load_calib` 全部失败，程序却继续往下跑。

## 2. 内参：四次多项式 ρ(θ)

```
ρ(θ) = k1·θ + k2·θ² + k3·θ³ + k4·θ⁴

χ  = √(X² + Y²)
θ  = atan2(χ, Z)
u' = ρ·X/χ                       (χ=0 时为 0)
v' = ρ·Y/χ
u  = u' + cx_offset + width/2 − 0.5
v  = v'·aspect_ratio + cy_offset + height/2 − 0.5
```

### 2.1 与 KB 模型的区别（关键）

| | KB（项目理想基线） | RADIAL_POLY（hanqtech） |
|---|---|---|
| 形式 | `r = f·[θ + k1θ³ + k2θ⁵ + …]` | `ρ = k1θ + k2θ² + k3θ³ + k4θ⁴` |
| 项次 | 只有奇次 | **含偶次** |
| 焦距 | 单独给 `f` | **k1 就是焦距**（px/rad） |

**不能套用同一组系数**。hanqtech FV 的 `k1=339.75` 是焦距，
若当 KB 的畸变系数用，θ>0.2 rad 处投影完全失真。

代码：`NFCameraModelKind`（`NF_CAM_MODEL_KB` / `NF_CAM_MODEL_RADIAL_POLY`）。
内部用 `model_scale()` 统一两者：`r_pixel = K · theta_d_normalized(θ)`，
KB 时 `K=f`，RADIAL_POLY 时 `K=k1`。

### 2.2 主点不等于 cx_offset

`cx_offset` 只有 3.9 px 量级，**不是主点像素坐标**。真正的主点是：

```
cx = cx_offset + width/2 − 0.5
```

实测四路：

| 相机 | cx_offset | 实际主点 cx | 图像中心 |
|---|---|---|---|
| FV | 3.942 | 643.44 | 640.0 |
| MVL | 1.829 | 641.33 | 640.0 |
| MVR | 3.468 | 642.97 | 640.0 |
| RV | 6.670 | 646.17 | 640.0 |

### 2.3 视场

四角 θ ≈ **112°**，ρ 多项式在 [0, 120°] 上单调。`max_theta` 取 120°。

## 3. 外参：与项目约定完全一致

readme 明示：camera → vehicle 的变换，四元数用 `Rotation.from_quat`（xyzw）。

实测三条全过：

| 项 | 结果 |
|---|---|
| `det(R)` | +1.000000 |
| `‖RRᵀ − I‖` | < 1e-6 |
| 相机 y 轴在车系 z 分量 | 四路均为负（朝下） |
| 光轴与径向夹角 cos | +0.126 ~ +0.923（朝外） |

**结论**：`NFPose.R = M`（行优先展平）、`NFPose.t = translation × 1000`（mm），
无需任何坐标变换。

### 3.1 真实安装角（与理想外参差别很大）

| 相机 | 光心 (mm) | 方位角 | **俯角** |
|---|---|---|---|
| FV | (3748, 0, 681) | −0.1° | **22.7°** |
| MVL | (1945, +957, 955) | +105.9° | **73.8°** |
| MVR | (1945, −957, 975) | −107.9° | **74.2°** |
| RV | (−1068, +55, 909) | +178.7° | **37.3°** |

**MVL/MVR 是侧下方俯视，不是侧视。** 这一点看图像确认过
（`docs/data_sample_quad.png`）：画面主体是车身侧面与下方路面。

## 4. 环带语义：绝对俯角（本节的结论改了一处既有实现）

视口环带 `EL_MIN=10°, EL_MAX=60°` 的含义**必须是绝对俯角（相对地面）**，
而不是相对光轴。

### 4.1 为什么

早期实现把环带角当"相对光轴"，在理想外参（俯角 0°）下恰好成立。
接入真实外参后完全失效：

| 解释 | FV 实际视口俯角 | 看到的地面距离 |
|---|---|---|
| 相对光轴 | 22.7 + 35 = **57.7°** | **432 mm**（车头正下方） |
| 绝对俯角 | **35.0°** | **973 mm** |

两种解释在真实 FV 图像上的投影点分布见 `docs/ring_semantics_check.png`：
红点（相对光轴）挤在画面下沿，绿点（绝对俯角）分布在中下部路面。

### 4.2 实现

```
视口像素 -> 视口系射线 rp（俯角 = 绝对俯角）
        -> 车系:  rw = R · rp
        -> 相机系: rc = Rᵀ · rw
        -> 鱼眼投影
```

`view_lut.cpp` 里不能直接把 `rp` 当相机系方向用。

## 5. 视口尺寸必须按真实图像算

视口宽 = **图像宽 / 降采样倍数**。

| 数据 | 图像 | downscale | 视口 | f |
|---|---|---|---|---|
| 理想基线 | 1920×1536 | 2 | 960×258 | 277.13 |
| hanqtech | 1280×966 | 2 | **640×172** | **184.75** |

`f = (W/2)/tan(hfov/2)`，W 变则 f 变，`B_MAX = numDisp·Z_MIN/f` 也要重算。

**踩坑**：视口宽写死 960 而图像是 1280 时，LUT 在错误位置采样，
warp 出来的视口图是乱的，但**不会报错**，只会让深度整体偏掉。

## 6. 位移从哪来

`vehicle_info/*.json` 字段：`speed / yawRate / steering / acceleration / distance / gear`。
**没有位姿**。

当前做法（简化，已标注局限）：

```
move_mm = ego_distance(m) × 1000 × (gear == 'R' ? -1 : +1)
车系位移 t = (move_mm, 0, 0)          行驶方向
相机系   t_C = Rᵀ · t                 各相机不同
```

**局限**：忽略横摆。本段数据 `yawRate≈0.43°/s`、两帧间隔未知，
横摆位移量级远小于纵向，暂按纯纵向处理。若要用于真实评测，
应由 `yawRate × dt` 补上横摆，或改用上游提供的位姿。
