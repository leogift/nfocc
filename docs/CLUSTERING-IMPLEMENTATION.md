## 1. 最终方案：纯网格哈希 + DBSCAN

对外接口名是 `nfocc_octree.h`（按八叉树语义使用），实现上是**纯网格哈希**。

### 1.1 为什么放弃树结构（六次迭代的记录）

150k 点、eps=120mm 实测：

| 版本 | 结构 | DBSCAN 耗时 | 失败原因 |
|---|---|---|---|
| v1 | 固定叶 200mm | 857 ms | 稠密区单叶 586 点，叶内退化 |
| v2 | 自适应细分 + 全遍历叶表 | 3281 ms | 25325 叶全扫 |
| v3 | 自适应细分 + x 方向二分 | 417 ms | 候选区间仍宽 |
| v4 | 自适应细分 + **逐层**哈希 | 4058 ms | 每层每点扫 2197 格 × 10 层 |
| v5 | 自适应细分 + 单层哈希 | 查不到点 | 叶跨多个深度，粗叶无索引 |
| v6 | 统一深度 + 单层哈希 | **段错误** | CSR/节点编号/哈希三者不一致 |
| **v7** | **纯网格哈希** | **45 ms** | — |

**共同失败点**：前六版都需要维护多个数据结构之间的一致性（父子链、节点 CSR 区间、哈希叶编号）。任何一处不同步，症状表现为"查不到"或"段错误"，而根因离得很远。

纯网格哈希只有一个结构 `(ix,iy,iz) -> 点列表`，逻辑上不可能不一致。

### 1.2 格边长的实测选型

| 格边长 | 均匀分布 格数/均点 | 均匀 dbscan | 极密团簇 dbscan |
|---|---|---|---|
| 40mm | 143956 / 1.0 | 313 ms | 335 ms |
| 80mm | 116261 / 1.3 | 79 ms | 250 ms |
| **120mm** | **83017 / 1.8** | **45 ms** | 283 ms |

格 = eps 时查询恰好覆盖 3×3×3=27 格，是最小安全覆盖。**不跟体素网格（200mm）对齐**——体素要融合，索引要查询，两者服务对象不同。

## 2. 动静分离

### 2.1 点级速度的位姿补偿（这里踩过坑）

`nf_point_velocity` 要把本帧点变换到上一帧坐标系再找最近邻。变换方向我第一版写反了：

```
墙在 x=3000（上帧，自车 x=0）。自车前进 500 后本帧看到墙在 x=2500。
R=I, t=(500,0,0)

错误写法 P_prev = Rᵀ(P_cur - t):  2500 - 500 = 2000  ✗
正确写法 P_prev = Rᵀ·P_cur + t:   2500 + 500 = 3000  ✓
```

差别在于 t 表示"上帧原点在本帧的位置"还是"本帧原点在上帧的位置"。接口选后者（自车位移，上游里程计给的就是"走了多远"）。

**负对照守住了这条**：不给位姿时静止墙的速度是 3080 mm/s（正确被判为"动"），给了位姿后是 0 mm/s。没有负对照，这个 bug 会让所有点都判"动态"而"看起来在工作"。

### 2.2 簇级投票

一簇内动态点占比超过 50% 则整簇判动态。抵消点级速度的随机误差。

## 3. 实测结果

### 3.1 判定质量

| 场景 | 输入 | 结果 | 判据 |
|---|---|---|---|
| 两团分离点 | 800 点 | 2 簇，噪声 0 | ✓ 应恰好 2 簇 |
| 密团 + 200 孤立点 | 600 点 | 1 簇，噪声 200 | ✓ 孤立点全部判噪声 |
| 全部孤立 | 50 点 | 0 簇，噪声 50 | ✓ 无核心点则无簇 |
| 静止墙（有补偿） | 100 点 | 速度 0 | ✓ 应≈0 |
| 静止墙（无补偿） | 100 点 | 速度 3080 mm/s | ✓ 负对照，应≠0 |

**第二行是关键**：DBSCAN 的核心价值就是拒绝噪声。如果换成体素连通域，200 个孤立点会各自成一簇，输出 200 个假目标。

### 3.2 性能

| 分布 | 点数 | 构建 | DBSCAN | 说明 |
|---|---|---|---|---|
| 均匀（真实点云） | 150k | 2.4 ms | **45 ms** | 在 100 ms 预算内 |
| 极密团簇 | 150k | 2.4 ms | 264 ms | **算法性质，非索引缺陷** |

极密团簇慢是必然的：5000 点挤在半径 300mm 的球里，eps 球内点数上千，任何索引都救不了。真实 150k 点云密度对应平均间距 36mm、eps 球内约 161 点。

**性能判据只对均匀分布成立**，用极密团簇判"索引不够快"是错误结论。

### 3.3 真实数据（hanqtech 帧 164）

```
聚类: 1256 点 -> 82 簇, 噪声 926 (格 120mm x 1116, 最大 5 点/格)
```

**这个结果说明当前点云密度下聚类没有实际意义**：1256 点里有 926 个判噪声，剩下 330 个分 82 簇、每簇 4 点。一辆车在 5m 处应占约 50 个体素，而整帧才 1256 点。

根因是精度问题（σ_d 14–42 px 导致大量点被剔除），点密度上不来，聚类就聚不出物体。**聚类算法的正确性已由合成场景验证，价值要等点密度上来才体现。**

## 4. 可视化

`nfocc_viz` 新增两阶段输出：

| 文件 | 内容 |
|---|---|
| `viz/06_body_mask.ppm` | D1 车身掩码，4 联竖排，红色=遮挡区 |
| `viz/07_clusters.ppm` | 聚类 BEV，每簇一色，噪声灰，自车白十字 |

06 的价值是**看出掩到了哪**——覆盖率数字看不出位置对不对，而掩错区域在点数上只是"少了几个点"。
