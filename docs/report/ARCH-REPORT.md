## 1. 系统定位

NFOCC 解决的是**低速近场**的稠密感知：车速 3.6 km/h（1 m/s）以上、
0.5–5 m 范围内，用 4 路环视鱼眼 + 车辆自身运动构成的"移动双目"，
输出 3D 体素点云与 2D 柱状高程图。

它不依赖固定基线双目。**基线来自车辆自身位移**：同一相机在 t 与 t−Δt
两个时刻看到同一物体，两者视差与位移构成三角关系。这带来两个后果：

- 低速时基线不足（冻结点），高速时重叠视场不足（另一个冻结点）；
- 必须有时基线管理，且不能假设位移是刚性已知的。

这两点决定了整个架构的重心：**视口几何 + 基线状态机 + 伪点防御**。

### 2.2 几何与视口层

**虚拟相机视口**是整个系统的地基。所有视口按 `pitch = 0, roll = 0` 构造，
只有 yaw。真实相机外参**只决定"这个车系方向落在哪张鱼眼的哪个像素"**，
不参与视口朝向。

这条设计的直接收益：视口射线本身就在车体系，三角化阶段**禁止**再乘
`R_cam→veh`，否则会产生 20%–45% 的深度发散（"转两次"）。

6 视口规划（虚拟相机水平张角 150°、垂直 120°）：

| 视口 | 相机 | yaw | 作用 |
|---|---|---|---|
| FV_p−45 / FV_p+45 | FV | ∓45° | 直行时提供**横向基线** |
| RV_p−45 / RV_p+45 | RV | ±135° | 后向同上 |
| ML | MVL | +90° | 左侧 |
| MR | MVR | −90° | 右侧 |

前后各两个视口不是冗余：**单一前向视口的横向基线为 0**，直行时视差消失、
深度不可解。偏 45° 后横向基线 = `T·sin45° ≈ 0.707T`，才谈得上测距。

**视口 LUT** 是离线构建的反投影表：视口像素 → 车系单位射线 → 相机系 →
鱼眼畸变模型 → 原图像素坐标。运行时只做查表与双线性采样。

**四次多项式内参**：`ρ(θ) = k₁θ + k₂θ² + k₃θ³ + k₄θ⁴`，其中 `k₁` **本身就是
焦距**（≈340 px），不是畸变系数。套错成 KB 归一化模型会在 θ > 0.2 rad 处
完全失真。

**D1 车身掩码**：车体轮廓多边形光栅化为视口掩码，LUT 构建期就把车身像素
判为无效。车标、保险杠、车漆反光因此不会进点云——在源头掐灭，下游零代价。

### 2.3 算法层

**SGBM 视差**（8bit）负责侧向基线对；**径向膨胀匹配**负责前向——前向极线
从运动极点辐射出去，同一行内方向差可超过 90°，SGBM 的行对齐假设根本不成立。

**双基线状态机**维护 `PREV_SHORT` / `PREV_LONG` 两路参考帧：

- `b ≥ b_target (300mm)` → 用长基线高精度输出，长基线退役、短基线晋升；
- 否则用短基线（`b ≥ b_min = 200mm`）；
- `b > b_max (460mm)` → 重叠视场不足，强制重置；
- 航向漂移 `Δψ > 15°` → `FROZEN_ROT`，**同时清空参考帧队列**（否则恢复后
  会用到过期参考帧）。

**四重防御**：D1 车身射线剔除、D2 双向视差一致性软权重、D3 FoE 发散锥、
D4 双基线交叉验证。当前 D1/D3 已接入主链路，D2/D4 算法就绪但受数据通路限制
尚未接线（详见第 6 节）。

### 2.4 输出与基础设施

**体素哈希 + 柱体排布**：200 mm 体素、开放寻址、CMA 加权质心聚合。
输出侧把点按 `col = iy·nx + ix` 递增、同列内按 `iz` 升序排布，
再配 `zMap`（32 位位图）与 `zIndex`（前缀和）。下游查任意地表格子
只需 `points[zindex[col] .. zindex[col+1]-1]`，**O(1)**，无需哈希查找。

**σ 方差传播**：`σ_Z = (f·b/d)·√[(σ_d/d)² + σ_odom²]`，量化到 cm、
钳位 `[1,254]`、`255` 为哨兵。下游据此知道每个点"有多可信"。

## 3. 单帧 Pipeline

FIG_PIPE

八个阶段，四路相机独立并行：

1. **原图取 Y**：BT.601 加权（`0.299R + 0.587G + 0.114B`），不是三通道均值。
2. **视口 LUT 查表**：得到视口像素 → 原图像素映射。
3. **重采样**：双线性，**无效邻域不参与权重**——按 0 处理会在边缘造出假梯度。
4. **SGBM**：左右图 = 当前帧与参考帧的视口图，`d_max` 由 `f·b/Z_min` 给出。
5. **三角化**：叉积闭式解，**必须带物理上界**（20 m）。射线近平行时
   `den` 极小，`s₀` 会被放大到 1e6–1e11，那种退化解会堵在网格边界，
   表现为 BEV 只有单一方向有深度。
6. **D3 FoE 剔除**：视线与平移方向夹角 ≤ 8° 的点深度退化，直接丢弃。
7. **σ 量化**：按真实视差与真实基线算不确定度。
8. **体素插入**：CMA 聚合，σ 取最小（多次观测里只要有一次特别准，
   位置就该按准的那次算）。

## 4. 门控决策流

FIG_FLOW

门控的每一步都是"不满足就不产出"，但**不丢帧**——冻结状态照样向下游发消息，
否则下游无法区分"确实没有障碍"和"感知挂了"。

关键设计取舍：`b > b_max` 时不直接报错，而是**先尝试降级用短基线**，
短基线也不行才冻结。这样高速段仍有产出，只是精度降一档。

## 6. 未完成项与边界

诚实说明，避免把"算法就绪"当成"系统可用"：

| 项 | 状态 | 原因 |
|---|---|---|
| D2 软权重接线 | 算法+测试就绪，未接 | 需反向视差图，SGBM 当前只跑单向 |
| D4 交叉验证接线 | 算法+测试就绪，未接 | 需同一体素跑两套基线 |
| 双基线管理器接入 pipeline | 模块+测试就绪，未接 | `NFFrameInput` 只有相对位移，无绝对位姿 |
| ZLIB 探测回退 | 未做 | 仅影响 Windows MinGW 便携构建 |
| `depth_accuracy` | 仍失败 | 测量口径问题（视场外投影 clamp），非实现缺陷 |
| Aarch64 真机 | 未运行 | 交叉编译产物已审计，未上板 |

`depth_accuracy` 值得多说一句：SGBM 视差本身用独立探针验证过，
误差 0.9%（约 4 m 处 36 mm）；问题出在验证方法——把产出点投回真实相机
像素再求交，落在视场外的点会被 clamp 到无关位置，于是"真值"本身是错的。
这是**测试的问题**，不是链路的问题，但也不能因此说精度达标。

## 7. 结语

NFOCC 当前是一个**几何正确、防御部分接入、精度链未闭环**的系统。
几何部分（虚拟视口、坐标变换、三角化）已经用真实数据反复验证，
BEV 四方向覆盖成立；防御体系算法齐全，但只有 D1/D3 走进主链路。

下一步的优先级应该按"能否闭环精度"来排：先补 `depth_accuracy` 的测量
口径，再谈 D2/D4 接线——否则新加的防御没有可信的度量去验证它到底有用没用。
