# SPEC-OCCLUSION — 双向光流遮挡检测

补齐审计缺口 **G-4**。本文档定义：在什么图上算光流、判据式的确切形式、
`nOcclusion` 怎么起作用、以及与引擎置信度的合成顺序。

---

## 1. 为什么需要这一层（以及为什么不能只靠视差置信度）

运动双目的失效模式里，有一类和"匹配质量差"不同：**遮挡区**。

车辆运动时：
- **遮挡（occlusion）**：前景物体盖住背景，背景在下一帧"消失"→ 背景像素找不到对应点；
- **去遮挡（dis-occlusion）**：原本被挡的区域露出来 → 新区域在上一帧不存在。

这两类区域的匹配结果**不是"差"，而是"错得很自信"**：SGBM 或网络会给出一个
纹理上合理、几何上错误的视差。它们在体素里表现为"视差断裂带上的伪点"。

**关键区别**：引擎的置信度（`conf`）是对局部纹理可匹配性的度量，
而遮挡是**几何事件**，两者正交。所以必须单独检测，不能指望 `conf` 覆盖。

## 2. 在哪个图上算（由单 Y 通道决定）

| 选项 | 可用性 | 结论 |
|---|---|---|
| 在原鱼眼图上算 | 退化严重（鱼眼边缘光流方向差异大） | ✗ |
| **在极线对齐后的视口图上算** | 已有该图（`nf_view_warp` 的产物） | **采用** |
| 在视差图上算（用视差本身做"光流"） | 遮挡区视差就是错的，自我循环 | ✗ |

**结论：在视口图上算，且只沿水平方向**（因为视口已按极线重排，`SPEC-EPIPOLAR` §3）。
这样"光流"退化成 1D 水平位移，就是视差本身——但**必须独立于引擎重新算一遍**，
否则无法验证引擎的结果。

### 2.1 单 Y 通道下的匹配代价

单通道没有颜色，可用信息只有亮度与梯度。采用 **Census 变换 + 汉明距离**：

```
census(I, x, y) = 逐位比较 (x,y) 与 7x7 邻域的亮度 → 64 位
cost(x, d) = popcount(census_L(x) XOR census_R(x-d))
```

Census 对**曝光差异不敏感**（只比大小关系），这正是单 Y 通道最需要的性质。
若改用 SAD，昼夜/隧道口的光照突变会导致大面积失效。

## 3. 双向一致性判据（确切形式）

对左图每个像素 `x`：

```
1. 前向:  d_fwd(x) = argmin_{d∈[d_min,d_max]} cost_L→R(x, d)
2. 后向:  在右图 x - d_fwd(x) 处求
           d_bwd(x') = argmin_{d} cost_R→L(x', d),  x' = x - d_fwd(x)
3. 残差:  r(x) = | d_fwd(x) − d_bwd(x') |          （注意: 这里用减号, 见 §3.1）
```

**判据**：

$$r(x) > \tau_{occ} \implies \text{遮挡/去遮挡像素} \tag{3.1}$$

`τ_occ` 默认 **1.0 px**（`PARAM.md::OCC_TAU`）。依据：视差异常值在两方向上的偏差
通常 ≫ 1 px；而正常区的双向偏差在亚像素级别（若引擎做亚像素）。

### 3.1 符号澄清（与原文档的写法不同，必须注意）

原 NFOCC 文档写的是 `|d_fwd(x) + d_bwd(x + d_fwd(x))|`（**加号**）。

**这是两套不同的约定**：
- 若双向的定义都是"正值视差"（本规范 `SPEC-COORD` §4.2：`d > 0`，左右都指同一方向），
  则一致时应为 **`d_fwd ≈ d_bwd`**，残差用 **减号**；
- 原文档的加号对应"后向光流定义为反方向"的约定（`d_bwd` 为负）。

**本项目统一：两个方向都用同一个正号定义，残差用减号。**
`SPEC-COORD` §4.2 已经定了 `d > 0`，这里必须与之一致；用加号会导致
正常区被判成遮挡、遮挡区被判成正常，方向完全反。**V-OCC-2 专门抓这个。**

## 4. `nOcclusion` 的作用方式：软性压低，不做硬截断

### 4.1 为什么不硬截断

硬截断（残差超阈即 `valid = 0`）在纹理丰富区域会造成**成片的体素空洞**：
因为这些区域的残差分布长尾，大量正常像素偶发超阈。

### 4.2 软性压低公式

$$w_{occ}(x) = \frac{1}{1 + \lambda\cdot\max(0,\ r(x)/\tau_{occ} - 1)} \tag{4.2}$$

其中 `λ = OCC_LAMBDA`（`PARAM.md`，默认 14，对应原文档的 `nOcclusion`）。

| `r/τ` | `w_occ` | 含义 |
|---|---|---|
| ≤ 1 | 1.0 | 一致，不压低 |
| 2 | 1/15 ≈ 0.067 | 明显不一致，几乎剔除 |
| 5 | 1/57 ≈ 0.018 | 完全剔除 |

**`λ=14` 的依据**：`r/τ = 2` 时期望权重降到 1/15（即 95% 剔除），
`2−1=1`，`1+14×1=15`。原文档的 `nOcclusion=14` 在这个位置把曲线定死。

### 4.3 与引擎置信度的合成顺序

```
最终权重 w = conf_pre × w_occ × w_valid
```

其中：
- `w_valid` ∈ {0,1}：LUT 有效性（车身掩码、R_valid、图像边界）
- `w_occ` ∈ (0,1]：本规范的遮挡权重
- `conf_pre` ∈ [0,1]：推定的匹配置信度

**顺序不能反**：先算 `w_occ` 再乘，因为 `w_occ` 依赖独立的 census 匹配；
若先乘 `conf_pre` 再算遮挡，低置信像素会被排除在遮挡检测之外，反而漏检。

## 5. 与引擎的关系：两套视差怎么办

本模块独立算出一个 1D 稠密位移 `d_dof`，引擎也算出一个 `d_engine`。二者用途不同：

| 量 | 用途 | 精度要求 |
|---|---|---|
| `d_engine` | **输出视差**，进三角化 | 高（亚像素） |
| `d_dof` | **仅用于算 `w_occ`** | 低（整数像素足够） |

**不要把 `d_dof` 当输出**：Census + WTA 的精度远不如 SGBM 的半全局聚合。
它只负责回答"这个像素的双向一致性如何"。

**验收约束**：`|d_dof − d_engine|` 的中位数在非遮挡区应 < 1 px；
若差距更大，说明两者之一有问题（V-OCC-4）。

## 6. 计算量与平台约束

| 项 | 值 |
|---|---|
| 搜索范围 | `[d_min, d_max]`，与引擎同档 |
| 每像素代价 | 2 次 WTA（前向 + 后向）× `d_max` 次 census 比较 |
| 相对引擎开销 | 约 0.3–0.5 倍 SGBM（无半全局聚合，无亚像素） |
| 内存 | 只需一张 `d_fwd` + 一张 `d_bwd`（各 960×768 × 2 B ≈ 1.5 MB） |

**约束**：`d_max` 大时开销线性增长。`d_max=256`、960×768 时约 2.4 G 次 popcount，
在 RK3588 单核上预计数十 ms 量级——**必须与引擎并行或降采样计算**，
具体需实测（`PHASE` 的 PH-4）。

---

## 7. 失效语义

| 条件 | 动作 |
|---|---|
| `d_fwd` 落在搜索边界（`d = d_min` 或 `d = d_max`） | 标记为**不可信**（`w_occ = 0`），这是"超出搜索范围"而非"一致" |
| 后向搜索越界（`x' = x − d_fwd` 出图） | 同上 |
| Census 窗口跨 LUT 无效区 | 该像素 `w_occ = 0`（窗口含无效像素时 census 无意义） |
| 整帧 `w_occ=0` 像素比例 > 50% | 报 `NF_E_BASELINE_DEGRADED`，说明场景或参数异常 |

## 8. 验收

| 编号 | 级别 | 判据 | 负例（必须失败） |
|---|---|---|---|
| V-OCC-1 | L0 | 无遮挡的合成平移场景，`r(x)` 中位数 < 0.5 px | 用 SAD 替代 Census + 加亮度偏移 → 残差暴涨 |
| V-OCC-2 | **L0** | **构造已知遮挡（前景方块挡背景），该区 `r` 大于背景区 5 倍以上** | **判据用加号 → 正常区被判遮挡、遮挡区被判正常** |
| V-OCC-3 | L0 | `w_occ` 随 `r/τ` 单调递减，且 `r=2τ` 时 `w_occ ≈ 1/15` | `λ` 写成 1.4 → 曲线不符 |
| V-OCC-4 | L1 | 非遮挡区 `\|d_dof − d_engine\|` 中位数 < 1 px | 两者用不同符号约定 → 差距巨大 |
| V-OCC-5 | L0 | 边界像素（`d` 顶到搜索上限）被标为不可信，而非"一致" | 不判边界 → 超范围像素权重为 1 |
| V-OCC-6 | L1 | 遮挡区体素密度比不加遮挡检测时下降 > 50%，非遮挡区下降 < 5% | 硬截断 → 非遮挡区也大片下降 |

**V-OCC-2 是最关键的一条**：它用"已知遮挡"的合成场景，
同时验证判据符号、前后向定义、阈值三件事。符号错的话这条必然失败，
而单独看遮挡区的绝对数值未必能发现（方向反了也是"有差异"）。
