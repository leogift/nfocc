NFOCC 已对齐了核心几何防御、多帧双基线状态机与高程压缩，但相比完整的参考量产系统，在系统全景上仍存在以下6
  项关键差距与差异：

  1. 视口几何形态差异（柱面/圆锥面 vs 平面展开）
   * 参考量产系统：采用柱面视口（Cylindrical Viewport）与俯倾圆锥视口（Conical Viewport）。柱面可在侧向生成 360°
     水平极线，保持恒定角分辨率；圆锥面朝向地面，专为超近场路沿（Curb）、停车位地锁及限位杆设计，拥有专门的极坐标测距闭式解
     （R_{cyl} = f · b / d）。
   * NFOCC：采用 6 个理想针孔透视平面视口（FV/RV 各 ± 45^∘，ML/MR 0^∘）。
   * 差距/影响：NFOCC 能直接无缝兼容 OpenCV
     SGBM，但在广角边缘处存在透视拉伸畸变；当车身紧贴极低矮障碍物时，缺乏圆锥面的高密度俯视分辨率。

  2. 在线外参自校准与基线补偿缺失（Online Auto-Calibration）
   * 参考量产系统：具备 mosbaselinecorrection.cpp
     模块，利用相邻帧稠密光流残差与地平面单应矩阵（Homography），在线实时估计悬挂俯仰（Pitch）、横滚（Roll）变化与轮速打滑漂
     移，动态补偿基线长度 b。
   * NFOCC：假定底盘轮速与 IMU 提供的位姿是刚性真实的，没有任何在线外参抖动补偿或尺度修正机制。

  3. 3D 聚类与动静态目标分割缺失（Clustering & Motion Segmentation）
   * 参考量产系统：包含完整的后处理链条（staticclustering、dynamicclustering、motanalysis），将体素点云聚类为 3D Bounding
     Box，分离静态设施（墙壁、立柱）与动态目标（行人、对向车），并输出目标级速度矢量 \vec{v}。
   * NFOCC：功能边界止步于基础几何感知（Voxel 点云与 2D Height Map），将 3D 聚类与跟踪完全丢给下游。

  4. 图像级多层预处理与滤波弱化
   * 参考量产系统：配备了完整的图像引导滤波（imgguidedfilter.cpp）、双边高斯平滑以及针对视差空洞的散斑滤波（imgspeckle.cpp），在立
     体匹配前后均有降噪抑制。
   * NFOCC：直接依赖 OpenCV SGBM 自带的默认散斑过滤，在复杂光照（如地下车库地面强反光、强逆光）下的图像预处理能力较弱。

  5. 车规功能安全与通信冗余体系缺失（ASIL-B Safety Architecture）
   * 参考量产系统：基于 AUTOSAR / QNX 体系，输出 OBJC_cam_refsys_raw_input_S 结构，具备 CRC16 校验、每帧 Rolling Counter
     计数、心跳监视（Watchdog）与故障退化安全门控。
   * NFOCC：采用开源体系（ZeroMQ IPC / POSIX SHM），缺乏车规级数据链路完整性校验与防丢帧硬件重发保护。

  6. 多线程 Voxel 哈希的 Scratch Tile 缓存
   * 参考量产系统：在 OpenMP / 多核并发体素化时，为每个线程分配独立的局部 Tile Scratch 缓存，收集局部体素后批量归约至全局 Hash
     表，杜绝多核原子锁冲突。
   * NFOCC：目前采用单全局开放寻址哈希表，多相机并行时需依靠简单的槽位探查，高并发极限下的吞吐率弱于参考量产系统。

解读：# NFOCC vs参考量产系统六项差距的工程化弥合方案

以下逐项分析差距的**技术本质、风险等级、弥合路径与优先级**，最后给出依赖关系与分阶段实施路线。判断基准：若 NFOCC 定位为**可量产交付的环视感知模块**，六项均为必修项；若定位为**算法原型/研究平台**，则第 5 项可延后，第 1、2 项是最高优先。

---

## 差距 1：视口几何形态——柱面/圆锥面 vs 平面展开

**技术本质**：这不是“换一种投影”的等价替换，而是**极线搜索的几何前提**不同。平面针孔视口在 FOV 边缘的透视拉伸使角分辨率随视场角增大而恶化，SGBM 的固定视差搜索范围在边缘处对应的物理深度范围被严重压缩；柱面视口保持恒定角分辨率，圆锥视口为超近场地面提供高密度俯视采样。

**风险等级：中高**。不致命（平面视口能跑通 SGBM），但直接限制近场 0.3–1 m 的感知精度——而这恰是 APA 泊车最关键的区间。

**弥合路径（渐进式，不推翻现有架构）**：

1. **保留平面视口为 L0 保底路径**，新增柱面视口作为 L1 精度路径，两者共用同一套下游体素化与 Hash 模块——差异只在 LUT 构建与视差搜索的极线组织方式。
2. **圆锥视口作为专用近场模块**，仅覆盖车身四周 0–1.5 m 的地面环带，输出独立的“超近场高程补丁”，与主点云在体素层融合（同一 Hash 表，相同 mmPerVoxel）。
3. **柱面视口的关键实现约束**：极线必须严格落在同一图像行，残余行偏移用离线 LUT 逐行位移校正（亚像素预补偿），否则 SGBM 的行对齐假设不成立。
4. **圆锥视口的闭式解复用**：`R_cyl = f·b/d` 的极坐标反投影在 DSP 上仅为一次除法 + 一次三角函数查表，算力代价可接受。

**验收标准**：在 0.3–1.5 m 近场标定板场景，柱面+圆锥路径的体素位置偏差中位数比纯平面路径降低 ≥ 30%。

---

## 差距 2：在线外参自校准与基线补偿

**技术本质**：这是**量产系统与实验室系统的分水岭**。悬架压缩导致相机俯仰变化可达 ±1.5°，轮速打滑导致基线尺度误差可达 3%–5%。这些误差**不是标定能消除的**，因为它们是动态的、逐帧变化的。

**风险等级：高**。缺失此项意味着系统在真实车辆载荷变化、路面颠簸、轮胎磨损后精度持续退化，且**无自诊断能力**。

**弥合路径（参照参考量产系统的 `mosbaselinecorrection` 思路，但适配 NFOCC 的外部位姿基线架构）**：

1. **地平面单应矩阵在线估计**：利用相邻帧中可靠的地面特征点（车道线、停车位标线），估计帧间单应矩阵，分解出俯仰/横滚变化量，补偿相机外参。
2. **基线尺度自检**：在直线行驶段，用视差反算的已知宽度刚性目标（标定板或停车位）的宽度与先验比对，偏差 > 3% 时对基线施加尺度校正因子。这与前文 参考量产系统 V2 方案中提出的自检机制一致。
3. **陀螺仪与视觉的残差监控**：若视觉估计的帧间旋转与陀螺仪积分值的残差在连续 N 帧（建议 N=50）内单调上升，触发外参微调或诊断上报——用**趋势**而非瞬时值作为触发信号，避免动态场景误触发。
4. **失效降级**：自校准置信度低时，回退到标定外参并**放宽不确定度**，而非停止输出。

**验收标准**：在悬架压缩 ±1.5° 的注入工况下，体素位置偏差中位数 ≤ 150 mm（相对无补偿时的劣化不超过 50%）。

---

## 差距 3：3D 聚类与动静态目标分割

**技术本质**：NFOCC 当前输出的是**几何点云**，下游拿到的是“哪里有点”而非“那里是什么”。量产系统需要目标级输出（Bounding Box + 速度矢量），因为泊车规划直接消费的是**目标**而非**点**。

**风险等级：中**。若下游已有独立的聚类跟踪模块，此项可协商为接口边界问题；但若下游期望 NFOCC 提供目标级语义，则缺失此项意味着系统功能不完整。

**弥合路径**：

1. **静态聚类**：基于体素的欧氏聚类（或 DBSCAN 变体），将点云分割为独立簇，输出 3D Bounding Box。算力约束下建议使用**体素级聚类**而非点级聚类——先按 Hash 邻域合并，再对簇做包围盒拟合。
2. **动态分割**：利用多帧体素的**存在概率衰减**与**质心位移**区分静态设施与动态目标。静态体素的 CMA 质心稳定、计数持续累积；动态目标的体素质心随帧漂移、计数不稳定。
3. **速度矢量估计**：动态目标簇的质心帧间位移除以时间间隔，输出速度矢量。注意：运动双目本身的基线运动会使所有静态点产生“视差运动”，动态检测必须在**车辆坐标系**下做，而非相机坐标系。
4. **边界建议**：若决定不在 NFOCC 内做跟踪（仅做单帧聚类），则必须在 ICD 中明确输出格式，让下游知道拿到的是“单帧簇”而非“持续航迹”。

**验收标准**：在标准泊车场景（含行人、对向车、立柱、墙壁）中，静态/动态分类准确率 ≥ 90%，Bounding Box IoU ≥ 0.7。

---

## 差距 4：图像级多层预处理与滤波

**技术本质**：SGBM 自带的散斑过滤只处理**匹配后的孤立错误视差**，不处理**匹配前的图像质量问题**。地下车库地面强反光、强逆光、低纹理墙面——这些是匹配失败的前置原因，必须在匹配前干预。

**风险等级：中低**。这是六项中**最容易弥合**的，且投入产出比高。

**弥合路径**：

1. **匹配前预处理**：引导滤波（`imgguidedfilter` 等价实现）用于保边降噪；自适应直方图均衡（CLAHE）应对逆光；强反光区域用**梯度幅值门限**标记为低置信区，在 SGBM 中降低其匹配权重。
2. **匹配后滤波**：在 SGBM 的 `disp12MaxDiff` 之外，增加**散斑面积滤波**（剔除小于 N 像素的孤立视差块）与**亚像素一致性检查**。
3. **与置信度图联动**：预处理输出的低质量区域掩码，直接映射到视差置信度图，在体素化阶段跳过。
4. **实现优先级**：先做 CLAHE + 散斑面积滤波（低算力、高收益），引导滤波作为可选增强。

**验收标准**：在强反光与弱纹理场景中，有效视差点率提升 ≥ 15%，伪体素数量下降 ≥ 40%。

---

## 差距 5：车规功能安全与通信冗余（ASIL-B）

**技术本质**：开源 IPC（ZeroMQ/POSIX SHM）**没有数据完整性保证、没有防丢帧机制、没有心跳监控**。量产系统中，一帧损坏的体素数据可能导致规划模块做出错误避障决策。ASIL-B 要求的是**可证明的失效检测与降级路径**，而非“大概率不出错”。

**风险等级：高（若目标为量产）**。这是**架构级差距**，不能靠打补丁解决，必须在通信层重新设计。

**弥合路径**：

1. **数据链路完整性**：每帧输出增加 **CRC16 校验 + Rolling Counter + 时间戳**，接收端校验失败则丢弃并计数。
2. **心跳与看门狗**：生产者周期性发送心跳帧，消费者监测超时（建议 100 ms），超时触发降级（使用上一帧有效数据或输出“感知不可用”标志）。
3. **故障退化门控**：定义明确的降级状态机——正常 / 降级（部分传感器失效）/ 安全停止。每个状态对应下游可消费的输出语义。
4. **AUTOSAR 适配层（若平台要求）**：将现有 ZeroMQ 通道封装为 AUTOSAR 兼容的 E2E 保护（Profile 1 或 5），或至少在协议层实现等效的端到端保护。
5. **内存保护**：共享内存区域增加**只读映射**与**边界哨兵**，防止越界写入。

**验收标准**：注入随机位翻转、帧丢失、生产者崩溃三类故障，消费者均能在 ≤ 200 ms 内检测并进入定义的降级状态，不输出损坏数据。

---

## 差距 6：多线程 Voxel Hash 的 Scratch Tile 缓存

**技术本质**：单全局开放寻址哈希表在多核并发时，所有线程竞争同一张表，槽位探查的缓存行伪共享（false sharing）会严重拖累吞吐。参考量产系统的 Tile Scratch 方案本质是**空间分区 + 批量归约**，将并发冲突从“逐点”降到“逐 tile”。

**风险等级：中**。当前单全局表在低并发下可用，但多相机（4 路）并行体素化时吞吐率会成为瓶颈。

**弥合路径**：

1. **两级哈希结构**：每个线程（或每个相机）维护独立的局部 Scratch 哈希表，收集本线程的体素后，批量归约到全局表。归约时按 Hash ID 排序后合并，避免随机访问冲突。
2. **Tile 空间分区**：将体素网格按 XY 平面划分为 tile（如 16×16 体素/tile），每个线程负责固定 tile 集合，从空间上消除重叠写入。
3. **无锁归约**：全局表的合并阶段可用**分段锁**（按 Hash ID 高位分段）而非全表锁，进一步降低争用。
4. **内存预算**：Scratch 表的负载因子上限 0.7，探测深度上限 4（超过则丢弃并计数），与参考量产系统的工程约束一致。

**验收标准**：4 相机并行体素化时，吞吐率 ≥ 单线程的 3.2 倍（即并行效率 ≥ 80%），归约阶段无数据丢失。

---

## 依赖关系与实施优先级

六项差距并非独立，存在明确的依赖链：

```
差距 4（图像预处理）──→ 差距 1（视口几何）──→ 差距 2（在线标定）
                                    │
                                    ↓
                          差距 6（多线程 Hash）
                                    │
                                    ↓
                          差距 3（聚类分割）
                                    │
                                    ↓
                          差距 5（功能安全通信）
```

**分阶段建议**：

| 阶段 | 内容 | 理由 |
| :--- | :--- | :--- |
| **第一阶段（1–2 月）** | 差距 4（预处理）+ 差距 6（多线程 Hash） | 低风险、高收益、不改变架构，立即提升吞吐与鲁棒性 |
| **第二阶段（2–3 月）** | 差距 2（在线标定）+ 差距 1 的柱面视口 | 直接决定近场精度，是量产可用的前提 |
| **第三阶段（2–3 月，并行）** | 差距 5（功能安全通信层） | 架构级改造，需与下游协商接口契约，宜早启动 |
| **第四阶段（3–4 月）** | 差距 1 的圆锥视口 + 差距 3（聚类分割） | 圆锥视口是精度增强项；聚类可先做单帧静态聚类，动态跟踪视下游需求决定是否内置 |

**一句话判断**：差距 2（在线标定）和差距 5（功能安全）是**量产门槛项**，不可协商；差距 1（视口）和差距 6（多线程）是**性能关键项**，决定系统上限；差距 3（聚类）和差距 4（预处理）是**功能完整性项**，可按下游接口边界灵活取舍。建议以“**先保量产门槛、再提性能上限、最后补功能完整性**”的顺序推进。
