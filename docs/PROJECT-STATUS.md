## 4. 缺口清单（按阻塞程度排序）

### G1 无真值场景 —— 最根本

**现状**：合成源用「纹理横移」模拟运动，不是真实 3D 场景投影。
没有地面、没有物体、没有激光真值，因此**无法回答"测出的距离对不对"**。
这正是原始阶段 A 验收标准（<150 mm）至今未验证的原因。

**影响**：所有精度数字（0.045 px 匹配精度、解析测距 0.000 mm）都是**中间量**精度，
不是**端到端深度**精度。两者不能互相替代。

**解法**：写一个解析可求真的合成场景 —— 平面地面 + 若干已知位置的竖直平面，
按真实相机模型渲染（射线-平面求交 → 投影 → 采样纹理）。
这样每个像素的真值深度可闭式求出，才能算端到端误差。

### G2 三重遮挡防御未实现

见 §2。D1 只需接线（低成本）；D2/D3 中等；D4 高价值。
**没有 D2/D4，点云里的伪点无法剔除**，直接给下游是危险的。

### G3 45° 偏转的精度未知

上一轮 30° 实测深度误差 −11%~+21%。45° 的视差更大（13.06 vs 9.24 px），
但极线离散也更差。**是否更准需要 G1 解决后才能测**。

### G4 验收清单未汇总

`SPEC-VERIFY.md` 有 39 项，只覆盖 CO/EPI/VOX/ENG/ICD/BS/PARAM。
后加的 TRI / FR / PROD / BUILD / LUT / CAL / UP / DS 都写在各自文档里，**未进总表**。
导致"总共该验多少、过了多少"无法一眼看出。

### G5 文档早于代码

多份文档停留在 11-01 15:11，早于视口偏转（17:xx）、上下游协议、ZLToolKit 移植。
`SPEC-LUT.md`、`SPEC-VOXEL.md`、`PARAM.md` 都需要按当前实现更新。

### G6 无真实数据

用户已明确排除。KB 系数 k1..k4 仍是 0（等距模型）；四路真实外参未标定。

## 5. 后续计划

按「先能证伪，再能交付」排序。每项都给出可执行判据。

### P1 建真值合成场景（G1）—— 最高优先

**做什么**：
1. `tools/synth_scene.cpp`：定义场景（地面 z=0，N 个竖直平面，可含斜坡），
   对每个视口像素做射线-平面求交，得到闭式真值深度
2. 按真值渲染两帧图像（当前帧 / 参考帧，位移 T）
3. 输出 `(image, ground_truth_depth)` 供 pipeline 比对

**判据**：地面真值深度与 `H/tan(el)` 解析值误差 < 1e-6 mm（自我校验）

**为什么必须先做**：没有它，后面所有精度工作都无法量化，只能靠"看起来合理"。

### P2 端到端深度精度验收（G1+G3）

**做什么**：用 P1 的场景跑完整 pipeline，统计
`|Z_measured − Z_truth|` 的中位数与 P95，按深度分档（1/2/3/5/9 m）。

**判据**（对齐原始阶段 A）：
- 1–3 m 中位误差 **< 150 mm**
- 若 45° 偏转不达标，回退测 30° / 35°，给出角度-精度曲线供决策

### P3 三重遮挡防御（G2）

分三小步，每步独立可验：
1. **D1 接线**：pipeline 传入车身掩码（按车辆 5000×2000 生成多边形），
   统计 `d4_body_mask` 非零
2. **D3 FoE 锥**：前向匹配已有 FoE，加锥体剔除，判据 = 锥内点产出为 0
3. **D4 双基线交叉验证**：FV 的 ±45° 两视口互为验证基线。
   判据 = 注入一个虚假匹配点，验证后被剔除；真实点保留且 σ 减半

### P4 汇总验收清单（G4）

把 TRI/FR/PROD/BUILD/LUT/CAL/UP/DS 的验收项并入 `SPEC-VERIFY.md`，
形成唯一总表，并标注每项的**实际执行命令**与自动/手动。

**判据**：总表项数 == 各文档项数之和；`docs_check.py` 校验引用一致性。

### P5 文档同步（G5）

按当前代码更新 `SPEC-LUT`（偏转与 6 视口）、`SPEC-VOXEL`（CMA 实际参数）、
`PARAM`（新增 `view_hfov_deg`、偏转角）。已在仓库根 `../CHANGES.md` v0.7.0 记录的，
文档里要体现同样的结论。

### P6 模型引擎（阶段 C，无真实数据可先做骨架验证）

用随机权重的玩具 ONNX 打通推理路径：输入绑定、预处理、后处理到 `NFDisparityMap`。
**判据**：形状正确、全流程不崩、能产出视差图（数值无意义）。
真实精度等训练权重。

### P7 板端验证（G6 之外）

`aarch64` 产物已审计架构与依赖，但未在 RK3588/M57 上运行。
需要交叉编译 → 部署 → 跑 `test_geometry` 等纯计算测试（不需要真实数据）。

## 6. 建议的执行顺序

```
P1（真值场景）
 └→ P2（端到端精度）       ← 这一步才知道偏转角该选多少
      └→ P3（遮挡防御）    ← 有真值才能验证"剔除的是伪点"
P4（验收汇总）  P5（文档同步）   ← 可与上面并行
P6（模型骨架）  P7（板端）       ← 独立，随时可做
```

**P1 是一切的支点**。在它完成之前，任何"精度提升"的说法都无法证伪。
