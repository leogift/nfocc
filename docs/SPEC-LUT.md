# SPEC-LUT — 视口 LUT 的构建、存储与采样

补齐审计缺口 G-8 / K-1。当前实现：`cpp/src/lut/view_lut.cpp`、`cpp/include/nfocc/nfocc_lut.h`。

## 1. 两条链路的本质差别

| | 3D→2D BEV 采样 | 本项目的视口 LUT |
|---|---|---|
| 方向 | 遍历体素投到图像 | 遍历视口像素，反投影射线，再投到鱼眼 |
| 时机 | 在线，每次 forward | 离线，每个视口构建一次 |
| 网格 | 稠密体素 | 2D 视口栅格 |
| 用途 | 采样特征到 BEV | 把鱼眼重采样成理想针孔视口 |

不照抄 3D→2D 的原因：视口是图像域的；遍历 3D 体素去填一张 2D 视口图，
绝大多数采样落在同一像素上，浪费一个数量级。

## 2. 视口参数与 6 视口规划

### 2.1 输入输出

```
输入: NFCameraModel (KB 内参), NFPose (外参), NFViewParams (视口)
输出: NFViewLut {
        nf_i16 *u_q4;   // 鱼眼 u, Q12.4
        nf_i16 *v_q4;   // 鱼眼 v, Q12.4
        nf_u8  *valid;  // 0/1
        nf_u32  width, height;
      }
```

每栅格点 5 字节（u:2 + v:2 + valid:1）。前端 590×716 → 2.11 MB/视口，
侧视 1024×475 → 2.43 MB/视口；6 视口合计约 13.3 MB。

### 2.2 视口朝向：绝对 `yaw_deg`，没有 `yaw_offset`

`NFViewParams` 只有 `yaw_deg`（车系绝对 yaw，ISO 8855 逆时针正）、`pitch_deg`
（约定恒 0）、`roll`。**当前没有 `yaw_offset_deg`，也不做“视口跟随光轴”的
二次旋转。** 虚拟相机的基向量由 `pixel_to_ray_impl` 直接建在车系：

```
forward = ( cos yaw,  sin yaw, 0)   -> 视口 +z
right   = ( sin yaw, -cos yaw, 0)   -> 视口 +x
down    = ( 0, 0, -1)               -> 视口 +y
```

`(right, down, forward)` 不是右手排列，`t` 的投影/反投影必须用点积，不能用
`Rz(±yaw)`。这条在 `SPEC-CONVENTION.md` §2.4 有反例。

### 2.3 当前 6 视口表

| 视口 | 相机 | yaw | 张角 | 尺寸 | f (px/rad) | 匹配 |
|---|---|---|---|---|---|---|
| FV -45 | 0 FV | −45° | 110° | 590×716 | 206.6 | 径向（极点） |
| FV +45 | 0 FV | +45° | 110° | 590×716 | 206.6 | 径向 |
| RV -135 | 1 RV | −135° | 110° | 590×716 | 206.6 | 径向 |
| RV +135 | 1 RV | +135° | 110° | 590×716 | 206.6 | 径向 |
| ML +90 | 2 MVL | +90° | 150° | 1024×475 | 137.2 | SGBM |
| MR -90 | 3 MVR | −90° | 150° | 1024×475 | 137.2 | SGBM |

前后成对：中心相隔 90°，各 110° 张角，留 20° 重叠。90° 张角时两视口只在
0° 交于一点，正前方目标同时落在两边边缘；110° 的解析场景竖面中位从 1213 mm
降到 791 mm（见 `SFM-6VIEW.md`）。

### 2.4 为什么前后 110°、左右 150°

`f = (W/2)/tan(hfov/2)`。同样基线 278 mm、5 m 处：

| 视口 | f | 5 m 视差 | 覆盖 |
|---|---:|---:|---|
| 前后 110° | 206.6 | 11.5 px | 每对 [-100°, +100°]，中间 20° 重叠 |
| 左右 150° | 137.2 | 7.6 px | 单视口覆盖整侧 |

前后有重叠，可以收窄换角分辨率；左右没有重叠，只能放宽。150° 的 f 只有
110° 的 66%，同样基线的视差也只剩 66%。

### 2.5 Q12.4

| 格式 | 精度 | 范围 | 大小 |
|---|---|---|---|
| float32 ×2 | 极高 | ±3.4e38 | 8 B/点 |
| **Q12.4 (int16)** | **1/16 px** | ±2047.9 px | **4 B/点** |
| Q8.8 (uint16) | 1/256 px | 0–255 px | 4 B/点（范围不够） |

Q12.4 的 1/16 px 与 SGBM 亚像素同量级；±2047.9 px 覆盖 1280 宽有余。
无效点的 `u_q4/v_q4` 写 `NF_LUT_SENTINEL`（0xFFFF），不能写 (0,0)——
左上角是合法像素。

## 3. 投影链

对每个视口栅格点 `(up, vp)`：

```
Step 1  视口像素 -> 车系射线
        rp = pixel_to_ray_impl(vp, el_mid, up+0.5, vp+0.5)
        rp 已经是车系单位向量（f/r/d 三个基向量都在车系）

Step 2  车系 -> 该相机系
        rc[k] = Σ_j pose->R[j*3+k] * rp[j]      // v_C = Rᵀ · v_V

Step 3  相机系射线 -> 鱼眼像素
        nf_vcam_project(cam, rc, &uf, &vf, &ok)
        只有 vcam 一个后端；不支持的模型判无效，不静默换实现

Step 4  有效性判定（§4）

Step 5  写 Q12.4
```

没有“按 t 重排视口”的在线步骤。`NFViewParams.reorient` 是预留字段，当前
未使用；6 个视口各自固定一个 yaw，LUT 构建一次，运行期只做 `nf_view_warp`。

### 3.1 三个容易写错的点

1. **主点处 `chi→0`**：`scale = rho/chi` 在 chi<1e-6 时取极限 1，否则 0/0=NaN。
2. **鱼眼有效性用 θ，不用 z>0**：θ 可以 >90°，此时 `rc[2]<0` 但鱼眼仍可能有像素；
   反过来相机系 `rc[2]<=0` 的射线在相机后方，必须判无效。两者不要混。
3. **真实外参只出现在 Step 2**：它决定“这个车系方向落在哪张鱼眼的哪个像素”，
   不参与视口朝向。视口朝向只由 `yaw_deg` 决定。

## 4. 有效性判定

按代码顺序：

```
G0  相机系朝前: rc[2] > 0
G1  vcam 投影 ok
G2  uf/vf 在图像范围（vcam 对越界返回 ok=0；代码另有 1920×1536 上限检查）
G3  r_img = f·θ_d <= r_valid
G4  θ <= max_theta
G5  车身掩码：按相机主点推导 mw=2·cx、mh=2·cy；hanqtech 为 1280×966
G6  Q12.4 量化不溢出
```

`NFLutStats` 分别记录 `d1_out_of_image / d2_out_of_r_valid / d3_over_max_theta /
d4_body_mask`，便于定位是标定、张角还是掩码问题。`d4_body_mask` 也复用给
`rc[2]<=0` 的几何无效计数。

全空视口返回 `NF_E_LUT_EMPTY`，但 `nf_pipeline_create` 不因此整条失败：
RV 朝车头这类方向本来就拍不到，只禁用该视口。

## 5. 双线性采样

`nf_view_warp` 对每个有效 LUT 点取鱼眼四邻域：

| 四邻域 | 处理 |
|---|---|
| 全 valid | 正常双线性 |
| 部分 valid | 按 valid 重归一化权重，不把无效当 0 |
| 全 invalid | 输出 valid=0 |

无效点当 0 会在鱼眼边缘制造假梯度，SGBM 会把它当纹理，产生伪视差。

## 6. 内存与构建

| 项 | 值 |
|---|---:|
| 前端单视口 LUT | 590×716×5 ≈ 2.11 MB |
| 侧视单视口 LUT | 1024×475×5 ≈ 2.43 MB |
| 6 视口 LUT | ≈ 13.3 MB |
| 视口图 + 有效位 + 视差图 | 12 B/px；6 视口约 41 MB |
| SGBM cost volume | 单引擎、串行复用；不按视口数乘 |

构建时间未单独计时；LUT 只在 `nf_pipeline_create` 建一次，不在每帧重建。

## 7. 验收

| 编号 | 判据 | 负例 |
|---|---|---|
| V-LUT-1 | 每格 `(u,v)` 与反投影再正投影一致（<0.01 px） | 正/反投影约定混用 |
| V-LUT-2 | 主点 `chi→0` 无 NaN | 不做极限处理 |
| V-LUT-3 | `max_theta` 显式给 2.235 rad 时边缘有效；改成 1.65 时边缘无效 | 用库默认 1.65 |
| V-LUT-4 | `valid=0` 处 `u/v=0xFFFF` | 写 (0,0) |
| V-LUT-5 | 6 视口各自 LUT 的 yaw/尺寸与 `nf_viewplan_default` 一致 | 所有视口共用同一 `NFViewParams` |
| V-LUT-6 | Q12.4 溢出点标 valid=0 | 直接强转 int16 回绕 |
| V-LUT-7 | `nf_view_warp` 有效区与原图相关系数 >0.999 | 无效点当 0 |

V-LUT-3 与 V-LUT-6 是两个真实踩过的坑：前者是库默认裁角，后者是 Q 格式边界。
