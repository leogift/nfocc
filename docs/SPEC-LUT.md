# SPEC-LUT — 视口 LUT 的构建、存储与采样

补齐审计缺口 **G-8 / K-1**。

**借鉴来源**：`/Volumes/Workspace/SimpleOCC/projects/mmdet3d_plugin/models/necks/view_transformer.py`
的 `SimpleViewTransformer.project_voxel_to_img()`（3D→2D 投影链）与
`projects/mmdet3d_plugin/core/cameras/fisheye_kb.py`（KB 正/反投影）。
**借鉴的是"投影链的组织方式与若干个已踩过的坑"，不是代码。**

---

## 1. 两条链路的本质差别（必须先分清，否则照抄会错）

| | SimpleBEV / ViewTransformer | 本项目的视口 LUT |
|---|---|---|
| 方向 | **3D → 2D**：遍历体素，投到图像上采样 | **2D → 3D → 2D**：遍历视口像素，反投影射线，再投到鱼眼像素 |
| 时机 | **在线**（每次 forward 算一遍） | **离线**（构建一次，运行期只查表） |
| 体素网格 | 稠密 `(Dz,Dy,Dx)` | 不需要体素（视口是 2D 栅格） |
| 用途 | 采样图像特征到 BEV | 把鱼眼图重采样成极线对齐的视口图 |

**为什么不照抄"3D→2D 遍历体素"**：本系统的视口是**图像域**的，不是体素域；
遍历 81000 个体素去填充一张 960×768 的视口图，绝大部分采样落在同一像素上，浪费 100 倍。

**但它的投影链写法值得借用**，见 §3。

## 2. 视口 LUT 的定义

### 2.1 输入输出

```
输入: NFCameraModel (KB 内参), NFPose (外参), NFViewParams (视口), t_rel (可选)
输出: NFViewLut {
        nf_u16 *u_q4;      // 每个视口栅格点的鱼眼 u, Q12.4
        nf_u16 *v_q4;      // 鱼眼 v, Q12.4
        nf_u8  *valid;     // 0/1
        nf_u32  width, height;   // = 视口尺寸
      }
```

**每栅格点固定 5 字节**（u:2 + v:2 + valid:1）。960×768 视口 → **3.54 MB**，可全驻留。


### 2.3 视口偏转（yaw_offset，v0.7.0 新增）

**为什么要偏转**：前后相机在直行时，平移沿光轴，横向基线 = 0，
视差深度**结构性消失**。把视口绕相机 y 轴偏开后，平移在视口系的
横向分量 = `T·sin(yaw)`，视差重新出现：

| 偏转 | 横向基线 (T=200mm) | Z=3m 视差 (f=277.13) |
|---|---|---|
| 0° | 0 mm | **0.00 px** |
| 30° | 100 mm | 9.24 px |
| **45°** | **141 mm** | **13.06 px** |
| 60° | 173 mm | 16.00 px |

**实现**：`pixel_to_ray_impl` 输出视口系射线后，绕相机 y 轴旋转
`vp->yaw_offset_deg`，再送 `nf_vcam_project`。相机不动，只是换采样方向。

```
ray = (sin(az)·cos(el), sin(el), cos(az)·cos(el))
若 yaw_offset != 0:
    x' =  x·cos(yaw) + z·sin(yaw)
    z' = -x·sin(yaw) + z·cos(yaw)
```

**符号约定**：`yaw_offset > 0` 时视口朝相机 +x（右）偏。
因相机 y 轴朝下，绕它转正角在车系里是**顺时针**，
故视口车系方位角 = `相机 yaw − yaw_offset`。

### 2.4 6 视口规划（定案配置）

| 视口 | 相机 | 光轴 yaw | 偏转 | 视口方位角 |
|---|---|---|---|---|
| 0 | ML | +90° | 0° | +90° |
| 1 | MR | −90° | 0° | −90° |
| 2 | FV | 0° | −45° | +45° |
| 3 | FV | 0° | +45° | −45° |
| 4 | RV | 180° | −45° | −135° |
| 5 | RV | 180° | +45° | +135° |

覆盖：每视口水平 ±60°，6 视口在全部方位角上至少 **2 重覆盖**，无空洞。
定义见 `nfocc_viewplan.h::nf_viewplan_default()`（唯一定义处）。

### 2.5 偏转的代价：有效像素下降（实测）

| 偏转 | LUT 有效率 | 出图外 | 超 r_valid |
|---|---|---|---|
| 0° / 30° | 100.0% | 0 | 0 |
| **45°** | **94.3%** | 3219 | 10786 |
| 60° | 76.0% | 3166 | 56363 |

**这是几何必然，不是缺陷**：视口水平 ±60°，偏 45° 后边缘到达光轴 105°，
超出鱼眼水平视场 100°，约 5.7% 像素落在有效圆外。

### 2.6 视锥张角不可随意加大

`f = (W/2)/tan(hfov/2)`，张角与焦距成反比：

| 张角 | f (px/rad) | 角分辨率 | 同基线视差 | 直行+45° 点云 |
|---|---|---|---|---|
| **120°（定案）** | 277.13 | 0.2067 °/px | 100% | 103 点 |
| 150° | 128.62 | 0.4455 °/px | **46%** | 85 点 |

覆盖上 120° 与 150° **完全相同**（6 视口已 2~3 重）；
150° 不增加覆盖、只损失视差分辨率。故定案 120°。

### 2.2 为什么用 Q12.4（不是 float）

| 格式 | 精度 | 范围 | 大小 |
|---|---|---|---|
| float32 ×2 | 极高 | ±3.4e38 | 8 B/点 |
| **Q12.4 (int16)** | **1/16 px** | ±2048 px | **4 B/点** |
| Q8.8 (uint16) | 1/256 px | 0–255 px | 4 B/点（**范围不够**） |

Q12.4 的 1/16 px 与 SGBM 的亚像素精度同量级；±2048 px 覆盖 1920 宽有余。
**Q8.8 的 1/256 px 精度更诱人，但范围只有 255 px，完全不够**——这是一个容易选错的地方。

### 2.3 无效点的表示（不能用 (0,0)）

`(u,v) = (0,0)` 是合法的左上角像素。**无效点必须靠独立的 `valid` 数组**，
且 `valid=0` 时 `u_q4/v_q4` 的值必须是 **0xFFFF**（哨兵），便于调试时肉眼识别。

## 3. 投影链（唯一实现，借用 ViewTransformer 的组织方式）

对每个视口栅格点 `(up, vp)`：

```
Step 1  视口像素 → 视口射线 (相机系 P)
        x = (up + 0.5 − cx_v) / f_v
        y = (vp + 0.5 − cy_v) / f_v
        r = sqrt(x² + y²)
        ray_P = normalize(x, y, 1)             ← 视口是针孔(SPEC-COORD 1.4)

Step 2  视口系 → 相机系:  ray_C = R_pc · ray_P
        其中 R_pc 由 t_rel 与 R_cv 决定        ← SPEC-EPIPOLAR §3 的视口重排
        (不重排时 R_pc = I)

Step 3  相机系射线 → 鱼眼像素 (KB 正投影)
        θ = atan2(sqrt(ray_C.x² + ray_C.y²), ray_C.z)
        θ_d = θ(1 + k1θ² + k2θ⁴ + k3θ⁶ + k4θ⁸)
        r_img = f · θ_d
        uf = cx + r_img · ray_C.x / chi
        vf = cy + r_img · ray_C.y / chi        ← SPEC-COORD 3.1

Step 4  有效性判定（顺序不可换，见 §4）
Step 5  写 Q12.4
```

### 3.1 借用的三个写法（来自 ViewTransformer，已在其代码里验证过）

**（1）`chi → 0` 的极限处理**（`fisheye_kb.py:96-99`）

```
chi = sqrt(x² + y²)
scale = rho / chi,  当 chi < eps 时 limit 为 1
```

不处理会在主点处 `0/0 = NaN`。**本规范要求同样的处理，`eps = 1e-6`。**

**（2）`rho → 0` 的反解初值**（`fisheye_kb.py:58-59`）

Newton 迭代初值取 `θ⁰ = ρ`（畸变小时已很接近），而不是 0。
**本规范沿用**，迭代 8 次（`SPEC-COORD` 3.3 原写 10 次，改用 8 次并加收敛断言）。

**（3）鱼眼的有效性不能用 `z > 0` 判**（`view_transformer.py:399-411` 的注释）

> `fisheye_kb -> euclidean range ||p||, because a Kannala-Brandt image radius encodes
> the INCIDENT ANGLE, not axial depth`

这句话在 BEV 里是"深度裁剪"的语义问题；在本项目里对应一个**更关键的点**：
**鱼眼的有效判据是 θ，不是 z**。θ 可以 >90°（射线朝后），此时 `z < 0` 但图像上仍有有效像素。
用 `z > 0` 判会把鱼眼超过 90° 的那部分视场整体丢掉。

## 4. 有效性判定（四道检查，顺序不可换）

```
D1  图像边界:  0 ≤ uf < 1920 且 0 ≤ vf < 1536
D2  有效半径:  r_img = f·θ_d ≤ r_valid          ← SPEC-CALIB-CFG §2.2
D3  角度上限:  θ ≤ max_theta                    ← 必须显式给定, 不用库默认
D4  车身掩码:  查 NFCarBodyMask                  ← SPEC-MASK §3
```

**顺序的理由**：
- D1 必须最先（后面都要用 uf/vf 索引）；
- D2/D3 是几何有效性，先于掩码（掩码查表要求坐标合法）；
- D4 最后（掩码是在像素空间查的）。

**D3 是必须的，不能省**：实测 `SimpleOCC` 的 `kb_project_points` 在
`max_theta=None` 时默认裁到 **1.65 rad（94.5°）**
［`fisheye_kb.py:112`］。对 f=550、1920 宽的相机，**左右边缘 θ=100°**
会被静默判无效。**必须显式传 `max_theta`（本例 2.235 rad）。**

## 5. 双线性采样的边界处理（`nf_view_warp`）

设 `uf = u0 + du`（`u0 = floor(uf)`，`du` 为小数）：

| 四邻域情况 | 处理 |
|---|---|
| 四点全 valid | 正常双线性 |
| 部分 valid | **按 valid 重归一化权重**（不是直接当 0） |
| 全 invalid | 输出 `valid = 0` |

**为什么不能把无效点当 0**：鱼眼图像边缘是暗的，无效点当 0 会在边缘产生虚假梯度，
SGBM 会把它当成纹理去匹配，反而制造伪视差。

## 6. 视口重排时的 LUT 更新策略（性能关键）

`SPEC-EPIPOLAR` §3 要求按 `t` 方向重排视口。若每帧都重建 LUT（960×768 = 73.7 万点，
每点一次 Newton 迭代），代价是**每帧数百万次浮点运算**，不可接受。

### 6.1 分解：离线部分 + 在线部分

关键在于把投影链拆成"与 t 无关"和"与 t 有关"两段：

```
ray_C = R_pc(t) · ray_P
```

`R_pc(t)` 是**每帧变化**的 3×3 旋转，而"ray_C → 鱼眼像素"（Step 3）与 t 无关。

| 方案 | 做法 | 每帧代价 |
|---|---|---|
| A 全重建 | 每帧跑完整链 | 73.7 万次 Newton，~50–100 ms |
| **B 旋转近似** | 把 `R_pc` 近似为绕视口光轴 2D 旋转 + 小角修正 | 一次 2D 重采样 |
| C 预存多份 | 按 yaw 分档预存 N 份 LUT，运行时插值 | 内存 ×N |

**推荐 B**：因为 `R_pc` 的作用只是"把视差方向转到视口水平"，
本质上接近绕光轴旋转；残余的俯仰分量用 `SPEC-EPIPOLAR` §3 的视口基向量处理，
这部分变化慢（随运动方向），可以**每 N 帧更新一次**而不是每帧。

### 6.2 量化约束

若采用 B，**必须验证**：重排后的 LUT 采样误差 < 0.25 px（`V-LUT-5`）。
否则 `SPEC-COORD` §6 的"LUT 精度 ≤ 1/16 px"就名存实亡。

## 8. 验收

| 编号 | 级别 | 判据 | 负例（必须失败） |
|---|---|---|---|
| V-LUT-1 | L0 | LUT 每格 `(u,v)` 与该格反投影射线再正投影的结果一致（< 0.01 px） | 正/反投影约定混用 → 偏差大 |
| V-LUT-2 | L0 | 主点处（`chi→0`）无 NaN | 不做极限处理 → NaN |
| V-LUT-3 | **L0** | **`max_theta` 显式给定为 2.235 时，左右边缘有效；改为 1.65 时左右边缘变无效** | **用库默认 1.65 → 静默丢 5.5° 视场** |
| V-LUT-4 | L0 | `valid=0` 处 `u_q4/v_q4 = 0xFFFF` | 无效点写 (0,0) → 与左上角混淆 |
| V-LUT-5 | L0 | 重排后 LUT 采样误差 < 0.25 px | 2D 近似误差过大 → 深度偏差 |
| V-LUT-6 | L0 | Q12.4 溢出（坐标 > 2047.9 px）的点被标 valid=0 | 直接强转 int16 → 回绕成负数 |
| V-LUT-7 | L1 | `nf_view_warp` 输出与原图在有效区亮度相关系数 > 0.999 | 无效点当 0 → 边缘出现假梯度 |

**V-LUT-3 与 V-LUT-6 是两个真实踩过的坑**：
前者来自 `SimpleOCC` 的库默认值，后者来自 Q 格式选择的边界。
