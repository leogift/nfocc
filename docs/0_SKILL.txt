1. 参考量产系统与 NFOCC 核心技术全景对比
================================================================================
NFOCC 是面向现代嵌入式边缘计算平台 (如 RK3588, Axera M57) 的开源原型实现，
而参考量产系统是在量产车规平台上长期验证的成熟商业系统。
两者在核心感知链条上的关键技术差异如下：

+---------------------+-------------------------------+-------------------------------+
| 技术维度            | NFOCC (当前开源基线)          | 参考量产系统 (量产工程平台)          |
+---------------------+-------------------------------+-------------------------------+
| 1. 视口几何形态     | 6个平面透视针孔展开视口       | 侧向大视场柱面 + 俯倾圆锥视口 |
| 2. 超广角拉伸控制   | 广角边缘存在透视拉伸失真      | 柱面等角步长采样，无透视拉伸  |
| 3. 低矮地锁/路沿    | 依赖外扩视口，分辨率较稀疏    | 专用圆锥俯视视口聚焦车轮近地  |
| 4. 在线外参校准     | 假定底盘位姿绝对刚性无偏差    | 地面单应矩阵光流在线校准俯仰  |
| 5. 目标级语义感知   | 仅输出原始点云与 2D 高程图    | 3D体素聚类、动静态分割与测速  |
| 6. 视差降噪滤波     | 仅依赖 OpenCV SGBM 默认后处理 | U8/U16 图像引导滤波+散斑剔除  |
| 7. 多核哈希并发     | 单一全局哈希表，存在原子锁竞争| 线程独立 Scratch Tile 局部缓存|
| 8. 车规功能安全     | 基础 ZeroMQ 通信，无安全包装  | ASIL-B 认证、CRC16+滚动计数   |
+---------------------+-------------------------------+-------------------------------+

2. 模块一：柱面与俯倾圆锥面极坐标光线采样及闭式测距反解
================================================================================
【业务痛点】
鱼眼相机视场角通常大于 190 度。若直接展开为平面针孔视口，图像边缘像素会出现严重的
切向拉伸（当入射角大于 60 度时，拉伸系数急剧增大）。
此外，泊车系统要求精准识别紧贴车轮的低矮路沿 (Curb)、地锁和限位杆，平面视口无法兼顾。

【参考量产系统算法原理】
参考量产系统抛弃了纯平面透视，设计了两种曲面展开射线模型：

1. 侧向柱面视口 (Cylindrical Viewport)
   - 围绕车身两侧建立虚拟圆柱面，半径为 Rc。
   - 水平方位角采用等弧度步长：theta(u) = (u - cx) * Delta_theta。
   - 垂直高度采用等间距步长：Y(v) = (v - cy) * Delta_y。
   - 视线单位向量公式：
     r_cyl(u, v) = (1 / sqrt(1 + Y^2)) * [ sin(theta), Y, cos(theta) ]^T
   - 优势：整个车身侧向保持严格均匀的角分辨率，水平极线在极坐标下完全平行。

2. 俯倾圆锥视口 (Conical Viewport)
   - 将圆柱母线向下旋转倾角 beta (通常为 20 到 35 度)，形成朝向地面的倒圆锥。
   - 视线向量通过 X 轴俯仰旋转矩阵实现：
     r_cone(u, v) = Rx(beta) * r_cyl(u, v)
   - 优势：光线高密度交织在车身外侧 0.3米 至 1.5米 的地表区域，路沿点云密度提升 3 倍。

3. 极坐标视差转 3D 物理点云闭式反解公式
   给定基线长度 b (mm) 与水平匹配视差 d (pixels)：
     ratio = b / d
     R_cyl = f_px * ratio                  (水平投影半径，mm)
     Z_view = n_px * ratio + offset_height (沿圆柱轴向高度，mm)
     X_view = R_cyl * sin(theta)
     Y_view = R_cyl * cos(theta)
   通过虚拟相机到车体外参转换，直接得到 ISO 8855 车身坐标系坐标。

4. Q12.4 定点查找表 (LUT) 规格
   - 每个网格点占 5 字节：
     * u_q12_4: 16位有符号整数 (前12位整数，后4位小数，分辨率 1/16 像素)
     * v_q12_4: 16位有符号整数
     * valid: 8位状态 (1=有效，0=车身掩码剔除或超出视场)
   - 嵌入式 SIMD 单周期双线性插值实现：
     frac_u = u_q12_4 & 0x0F;
     frac_v = v_q12_4 & 0x0F;
     int_u  = u_q12_4 >> 4;
     int_v  = v_q12_4 >> 4;

3. 模块二：在线外参自校准与悬挂/车轮打滑动态基线补偿
================================================================================
【业务痛点】
车辆在急加速、紧急制动或路面颠簸时，悬挂压缩会导致车身俯仰角 (Pitch) 产生 1.5 到
2.0 度的动态形变；雨雪湿滑路面还会导致轮速计产生 10%~20% 的车轮打滑。
若假定基线 b 固定不变，测距公式 Z = f * b / d 将直接产生同比例的线性距离失真。

【参考量产系统算法实现 (mosbaselinecorrection.cpp)】
1. 地平面单应矩阵 (Ground Plane Homography)
   设相机离地高度为 H_cam，法向量 n = [0, 1, 0]^T。
   在理想平地上，相邻两帧的理论变换矩阵为：
     H_ground = R_rel - (t_rel * n^T) / H_cam

2. 光流残差筛选地面特征
   - 在相邻图像间跟踪稠密光流，测得特征点对 (p_i, q_i)。
   - 计算地面残差：r_i = || q_i - H_ground * p_i ||。
   - 当 r_i < 1.5 像素时，判定该点为稳定地表特征点，排除动态障碍物干扰。

3. 最小二乘求解尺度因子与悬挂形变
   利用所有稳定地面点构建目标函数：
     min_{s, Delta_R} sum_i || q_i - (Delta_R * R_0 - s * t_0 * n^T / H_cam) * p_i ||^2
   - 解算得到尺度修正因子 s = b_true / b_odom。
   - 解算得到瞬时悬挂微小倾角 Delta_pitch 和 Delta_roll。

4. 平滑滤波与生效
   - 修正后的有效基线：b_corrected = s * b_odom。
   - 使用卡尔曼滤波或指数移动平均 (EMA, alpha=0.15) 进行时域平滑，杜绝高频跳变。

4. 模块三：3D 体素聚类、动静态分割与包围盒速度估计
================================================================================
【业务痛点】
底层的 3D 体素仅表示空间中某处“有障碍”。下游规划控制算法需要知道：
“这是一个静止的马路牙子，还是一个正在横穿的行人？他的运动速度是多少？”

【参考量产系统算法实现 (staticclustering, dynamicclustering, motanalysis)】
1. 2D 柱状连通域快速标记 (Column Connected Component Labeling)
   - 基于 2D 高程图 zMap 位图（每个柱体占用 32-bit）。
   - 仅对 zMap > 0 的活跃地表柱体执行 8-邻域连通域生长（Union-Find 算法）。
   - 垂直高度相交检验：相邻两柱体若存在垂直方向体素重叠或垂直间距 <= 200mm，则归为同一实体。

2. 跨帧匈牙利匹配与轨迹关联
   - 提取每个点云聚类簇的 3D 物理质心 C_k(t)。
   - 结合车辆自车位移补偿 t_ego，在历史聚类集合中通过匈牙利算法进行质心欧氏距离匹配：
     || C_k(t) - (C_j(t-Delta_t) + t_ego) || < 800 mm。

3. 自车运动解耦与绝对速度估计
   - 计算目标在世界坐标系的视在位移速度：v_obs = (C_k(t) - C_j(t-Delta_t)) / Delta_t。
   - 扣除车辆自身底盘速度：v_obj = v_obs - v_ego。

4. 动静态分类判定准则
   - 静态实体 (Static Obstacle)：|| v_obj || <= 0.2 m/s。
     类型：墙体、立柱、限位杆、道闸、路沿。
     输出属性：计算 3D AABB 最小外接包围盒，标记为不可穿透静态刚体。
   - 动态目标 (Dynamic Obstacle)：|| v_obj || > 0.2 m/s。
     类型：行人、过往车辆、宠物、自行车。
     输出属性：输出 3D 定向包围盒 (OBB)、航向角与 (vx, vy) 速度矢量。

5. 模块四：图像级保边引导滤波 (Guided Filter) 与散斑噪声剔除
================================================================================
【业务痛点】
传统立体匹配 (SGBM) 在地下车库光滑环氧地坪、大白墙等弱纹理区域极易出现大面积
视差空洞，同时在车辆边缘产生毛刺伪影。

【参考量产系统算法实现 (imgguidedfilter.cpp & imgspeckle.cpp)】
1. 保边引导滤波 (Guided Filter)
   - 以原始输入灰度图 I 作为引导图，对立体匹配生成的视差图 p 进行滤波，输出视差图 q。
   - 局部线性假设：在半径为 r 的窗口内，视差是灰度图的线性变换 q_i = a * I_i + b。
   - 解析闭式最优解：
     a = cov(I, p) / (var(I) + epsilon)
     b = mean(p) - a * mean(I)
     q = mean(a) * I + mean(b)
   - 参数推荐：窗口半径 r = 4，正则化系数 epsilon = 16.0 (针对 Q12.4 定点视差)。
   - 效果：低纹理区域被邻域平滑填充，同时在强对比边缘（如立柱边线）保持像素级陡峭过渡。

2. 散斑噪点剔除 (Speckle Filter)
   - 针对匹配失真产生的悬空孤岛“散斑点”，执行 4-连通域洪泛填充搜索。
   - 邻域连通条件：| d(x, y) - d(x+-1, y+-1) | <= 1.0 像素。
   - 过滤条件：若该连通区域内的总像素数 S < 100 像素，判定为噪点孤岛，将该区域内所有像素强制置零。

6. 模块五：多核并发 Scratch Tile 局部缓存与无锁并行归约
================================================================================
【业务痛点】
当使用 OpenMP 多线程（如 4 相机同时计算）向同一个全局 3D 哈希网格插入体素时，
频繁的多核原子操作 (std::atomic) 或自旋锁会导致 CPU 缓存行频繁颠簸 (Cache Bouncing)，
吞吐量随线程数增加反而严重劣化（4线程下性能损耗高达 58%）。

【参考量产系统算法实现 (mosvoxelisation.cpp)】
1. 空间分块划分 (Spatial Tiling)
   - 将地面长宽划分为若干固定大小的 Tile (例如 32 x 32 个体素网格为一个局部块)。

2. 线程私有局部缓存 (Thread-Local Scratch Tile)
   - 为每个工作线程分配独立的私有 Scratch Hash 缓存，尺寸极小，完全驻留在 L1/L2 缓存中。
   - 线程在处理本相机视口反投影时，点云只写入自己的 Scratch 缓存。
   - 相同格子的重复点在局部完成 CMA 累加，无任何锁竞争。

3. 条带化无锁批量归约 (Lock-Free Striped Reduction)
   - 帧末处理阶段，以 Tile 为单位进行 OpenMP 并行合并：
     #pragma omp parallel for schedule(static)
     for (int tile_id = 0; tile_id < NUM_TILES; ++tile_id) {
         mergeLocalTilesToGlobal(tile_id, worker_scratch_tables);
     }
   - 由于每个线程负责不同的全局 Tile 空间，写入内存地址互不相交，彻底消除了锁竞争，实现近乎线性的多核性能加速。

7. 模块六：车载 ASIL-B 功能安全、CRC 校验与 SERL 零拷贝共享内存交付
================================================================================
【业务痛点】
自动驾驶系统严禁任何未捕获的内存溢出、野指针、丢帧失效或通信数据静默损坏。
传统的 JSON/Protobuf 序列化开销大，且缺乏物理层面的端到端数据完整性保障。

【参考量产系统算法实现 (hkmc_nf_serl & DataFrameServer)】
1. 紧凑型点云二进制结构 (OBJC_cam_refsys_point_S)
   每个点严格紧凑排布为 12 字节（或 9 字节对齐传输）：
   - int16_t x_mm: 车身 X 坐标 [-32768, +32767] mm，覆盖 32 米范围
   - int16_t y_mm: 车身 Y 坐标 [-32768, +32767] mm
   - int16_t z_mm: 车身 Z 坐标 [-32768, +32767] mm
   - uint8_t source_camera: 相机来源掩码 (bit0=前, bit1=后, bit2=左, bit3=右)
   - uint8_t spatial_uncertainty_cm: 空间不确定度 (cm, 1~254, 255为无效)
   - uint8_t existence_probability: 存在置信度概率 (0 ~ 100%)
   - uint16_t nRawPoints: 累积观测命中原始光线数

2. 端到端功能安全校验机制 (Functional Safety)
   - 滚动计数器 (Rolling Counter): 0 到 255 循环递增，下游检测到跳变则告警。
   - CRC16-CCITT 校验码: 多项式 0x1021，初值 0xFFFF，对整帧数据流执行校验。
   - 系统降级状态机 (Graceful Degradation):
     * NORMAL: 正常四路环视输出
     * DEGRADED_EXTRINSICS: 单路相机外参偏差超 5 度，屏蔽该路并标记降级
     * DEGRADED_ODOMETRY: 底盘轮速信号超时 (>100ms)，冻结更新并通知下游刹停
     * FAILSAFE_FROZEN: 急转弯或视差奇异区，清空输出

3. DataFrameServer 零拷贝共享内存体系
   - 底层采用 POSIX 共享内存双缓冲 (Double Buffering) 机制。
   - 算法端作为 Producer 写入 Buffer A，写入完成后通过原子内存屏障切换指针。
   - 下游规划控制器作为 Consumer 直接只读挂载内存地址，实现 0 微秒内存拷贝传输。

8. 附录：核心参数推荐基准表与避坑指南
================================================================================
【核心工程参数基准】
- 体素栅格尺寸：Delta_vox = 200 mm (倒数系数 mmPerVoxelInv = 0.005)
- 感知包围盒 (ISO 8855)：
  * X 纵向：[-9000 mm, +9000 mm] (车前后各 9 米，网格数 nx = 90)
  * Y 横向：[-7500 mm, +7500 mm] (车左右各 7.5 米，网格数 ny = 75)
  * Z 垂直：[-500 mm, +2500 mm] (地下0.5米至地上2.5米，网格数 nz = 15)
- 基线门限：
  * b_min = 200 mm (对应车速 3.6 km/h 在 5Hz 下的单帧位移)
  * b_max = 460 mm (共视视场角下限)
  * b_target = 300 mm (并行双基线迭代切换目标)
- 伪影防御参数：
  * FoE 开锥半角：theta_cone = 8 度 (cos^2(8°) = 0.9806)
  * 双向光流容差：tau_occ = 1.0 像素，惩罚因子 lambda = 14.0
  * 双基线验证容差：Thresh_dist = 50 mm (达标则方差右移1位减半)

【高频技术避坑指南】
1. 坐标系旋转混淆：
   虚拟视口光线采样本身已经在车身坐标系内，千万不要在前向投影时再乘以相机外参矩阵 R。
2. 浮点除法开销：
   将所有体素坐标网格索引计算从除法 (/ 200.0) 全部改为乘法 (* 0.005)，嵌入式吞吐量显著提升。
3. 动态内存碎片：
   运行期（Process 循环内部）绝对禁止调用 malloc / new / std::vector::resize，
   所有临时点云、中间视差图与导出列表必须在初始化期由 FramePool 统一静态分配。
