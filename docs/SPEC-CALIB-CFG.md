# SPEC-CALIB-CFG — 相机配置（参数化，不写死）

本文档定义**相机内外参的配置文件格式与默认值**。原则：**任何几何量都必须可配，代码里不得出现字面量**。

用户已给的理想参数：

| 项 | 值 |
|---|---|
| 鱼眼焦距 `f` | **550 px** |
| 相机朝向 | **理想正前/正后/正左/正右**（无偏航偏移） |
| 车长 | 5000 mm |
| 车宽 | 2000 mm |
| 后轴到前端 | 3500 mm |
| 图像 | 1920 × 1536，单 Y |
| 内参模型 | KB 鱼眼 |

---

## 1. 由上述参数导出的几何（唯一来源）

车辆坐标系 = ISO 8855，原点在**后轴中心的地面投影**（`SPEC-COORD` §1.1）。

| 量 | 值 | 推导 |
|---|---|---|
| 后轴到前端 | +3500 mm | 用户给定 |
| 后轴到后端 | **−1500 mm** | 5000 − 3500 |
| 半边宽 | ±1000 mm | 2000 / 2 |
| `r_corner` | 1229.4 px | `√(960² + 768²)` |

### 1.1 相机安装位（理想正前后左右 = 车身四边中点）

```c
/* 单位 mm; yaw 为绕 Z 轴角度, 0 = 指向 +X */
POS_FV = { +3500,     0, POS_CAM_Z },  yaw =   0
POS_RV = { -1500,     0, POS_CAM_Z },  yaw = 180
POS_ML = {     0, +1000, POS_CAM_Z },  yaw =  90
POS_MR = {     0, -1000, POS_CAM_Z },  yaw = -90
```

**`POS_CAM_Z` = 700 mm**（相机安装高度，用户给定，可配）。
**`POS_PITCH` = 0°**（安装俯角，用户给定，可配），`POS_ROLL` = 0°。

三项全部来自 `PARAM.md`，代码里不得出现字面量。
**实测值不同时只改配置，不改代码**；`tools/calib_gen.py` 会按新值重算地面覆盖。

## 2. f=550 带来的两个必须处理的问题

### 2.1 视场超 180°，OpenCV/第三方 KB 实现会静默截断

`f = 550`、图像宽 1920 时，右边缘半径 960 px 对应：

$$\theta = \frac{960}{550} = 1.745\ \text{rad} = 100.0°$$

**已超过 90°，即这台鱼眼在水平方向确实看到了身后 10° 的范围**（典型 190–200° 鱼眼）。

| 位置 | r (px) | θ |
|---|---|---|
| 上下边缘 | 768 | 80.0° |
| 左右边缘 | 960 | **100.0°** |
| 四角 | 1229.4 | **128.1°** |

**实测过的坑**：`SimpleOCC` 的 `kb_project_points()` 在 `max_theta=None` 时
默认裁剪到 **1.65 rad（94.5°）**［`projects/mmdet3d_plugin/core/cameras/fisheye_kb.py:112`］。
用这台相机时，**左右边缘外 5.5° 会被静默判为无效**，且不报错。

**规范要求**：
```
- 调用任何 KB 投影函数必须显式传 max_theta = θ_max_of_camera
- θ_max_of_camera 由配置给出 (CAL_MAX_THETA), 不由库默认值决定
- 若裸用默认值 → 必须能通过 V-CAL-3 检测出来
```

### 2.2 四角 128° 一定无效，但**不要用固定半径判有效**

`r_valid` 若按短边（768 px）设，则左右边缘（960 px）也被判无效，**损失有效水平视场**；
若按长边（960 px）设，四角以外的区域全有效，**符合实际**。

**结论**：`r_valid` 默认取 **960 px**（长边半宽），而不是 768。
判别式是按半径的，所以"上下边缘 768 < 960 有效、左右 960 ≤ 960 有效、四角 1229 无效"——
恰好复现这台相机"左右看得更宽、四角被裁"的真实成像。

> 若实测发现厂商裁掉了左右边缘的图像（黑边），再按实测改小。**默认按 960。**

## 3. 配置文件格式

**唯一格式**：一个 `.py` 或 `.json` 均可，但字段名必须与下表一致，由 `tools/calib_gen.py` 生成 C 结构。

```json
{
  "version": 1,
  "vehicle": {
    "length_mm": 5000,
    "width_mm": 2000,
    "rear_axle_to_front_mm": 3500
  },
  "image": { "w": 1920, "h": 1536, "channels": 1, "dtype": "uint8" },
  "cameras": [
    {
      "id": "FV",
      "intr": { "model": "kb", "f": 550.0, "cx": 960.0, "cy": 768.0,
                "k": [0.0, 0.0, 0.0, 0.0], "r_valid": 960.0, "max_theta": 2.235 },
      "extr": { "pos_mm": [3500.0, 0.0, 700.0],
                "yaw_deg": 0.0, "pitch_deg": 0.0, "roll_deg": 0.0 }
    }
  ]
}
```

### 3.1 字段约束（违反即拒绝启动）

| 字段 | 约束 | 违反返回 |
|---|---|---|
| `w`/`h` | 必须 1920/1536 | `NF_E_PARAM_RANGE` |
| `intr.f` | > 0 | `NF_E_CAM_NOT_CALIBRATED` |
| `intr.max_theta` | ≥ 图像最远点的 θ（本例 128.1° = 2.235 rad） | `NF_E_PARAM_RANGE` |
| `intr.r_valid` | ≥ 0，且 ≤ `r_corner` | `NF_E_PARAM_RANGE` |
| `k[0..3]` | `θ_d` 在 `[0, max_theta]` 上单调 | `NF_E_CAM_DISTORT_INV` |
| 相机数 | 必须 4，且 id 恰好是 FV/RV/ML/MR | `NF_E_PARAM_RANGE` |
| `pos_mm` | 在车身包围盒内（±2500 × ±1000） | `NF_E_EXTRINSIC_INVALID` |

### 3.2 `max_theta` 的算法（不要手填）

$$\theta_{\max} = \arctan\!\left(\frac{r_{\text{corner}}}{f}\right)\ \text{（等距近似下即 } r/f\text{）} \tag{3.1}$$

本例：`1229.4 / 550 = 2.235 rad = 128.1°`。

**配置文件里可以写 `"max_theta": "auto"`，由代码按 (3.1) 算**，避免手填后与 f 不一致。

## 4. 由 f=550 重算的派生量

### 4.1 角分辨率

$$0.0990°/\text{px} \quad (=\frac{180}{\pi\cdot 550} \text{ rad/px} = 0.104°/px)$$

实算：`1/550 rad = 0.001818 rad = 0.1042°/px`。
（此前用 f=579 时是 0.0990°/px，**现在应更新为 0.1042°/px**。）

### 4.2 地面覆盖（f=550 时垂直半视场 = 80°）

f=550、H=1536 → 上下边缘半径 768 px → `θ = 768/550 = 1.396 rad = 80.0°`。
**垂直半视场 80° 非常大**，这意味着：

下边缘视线相对水平的俯角 `down = pitch + 80°`，上边缘 `up = pitch − 80°`。

| 俯角 `pitch` | `down` | 近端 `h/tan(down)` | 远端 |
|---|---|---|---|
| 0° | 80° | **123 mm** | 上边缘仰视，看到地平线 |
| 5° | 85° | 61 mm | 地平线 |
| 10° | 90° | **0（正下方）** | 地平线 |
| ≥10° | >90° | 0（能看到脚下与身后） | 地平线 |

**这不是笔误，是 f=550 + 1536 高的直接后果**：垂直半视场 80°，只要相机有一点俯角，
下边缘就翻过垂直线看到车底/身后。这带来两个真实问题：

1. **近端覆盖率极高，但没人想要"看车底"**——那部分视场对应的是自车与地面之间的空白，
   三角化出来全是噪声。**这部分必须靠视口裁剪（只取俯角 0–40° 的环带）而不是靠掩码。**
2. **`pitch < vhalf` 时上边缘永远仰视**，远端没有地面交点——
   所以"远端能看多远"完全由**视口的上边界**决定，不是由相机决定。

### 4.3 建议的视口裁剪（这是必须做的工程决策）

不要用整个 80° 垂直视场做立体匹配，而是裁剪到地面相关的环带：

| 视口垂直范围 | 地面覆盖（h=700, pitch=0） |
|---|---|
| 俯角 20°–50° | 255 mm – 1923 mm |
| 俯角 15°–55° | 490 mm – 2612 mm |
| 俯角 10°–50° | 587 mm – 3970 mm |

**推荐：俯角 15°–55° 环带**（约覆盖 0.5–2.6 m），对应 `PARAM.md` 的 `V_RING_*` 参数。
原因：`PARAM.md` 的 `B_ZMIN_EFF`（该档最近距离）与近端 490 mm 匹配；远端 2.6 m 在 200 mm 体素下
（`σ_Z` @2.6 m、b=120、f_view=550、σ_d=0.25 px 实算 **25.6 mm**）仍远小于体素。

**已定案：`POS_PITCH = 0`（水平朝前）。** 因此"近场地面在哪"完全由**视口环带**决定，
不是由相机姿态决定。环带按绝对俯角定义，与 `POS_PITCH` 解耦：

| `POS_PITCH` | 环带 10°–60° 相对光轴 | 地面覆盖 |
|---|---|---|
| 0° | 10°–60°（全在光轴下方） | 404–3970 mm |
| 15° | −5°–45°（下界略高于光轴） | 404–3970 mm（不变） |
| 30° | −20°–30° | 404–3970 mm（不变） |

**地面覆盖只由 `POS_CAM_Z` 与环带角决定，与 `POS_PITCH` 无关**——这正是把环带定义成
"绝对俯角"而不是"相对光轴角"的原因：换相机姿态不需要重算环带。
`tools/calib_gen.py --pitch 15` 已实测验证这一点。

### 4.4 视差量级（b=120 mm）

$$d = \frac{f_{\text{view}}\cdot b}{Z}$$

`f_view` 仍按视口张角决定（不直接等于 550：550 是原图内参，视口可能降采样）。
若视口 1:1 等于原图（`f_view = 550`）：

| Z | 0.5 m | 1 m | 2 m | 5 m |
|---|---|---|---|---|
| d (px) | 132 | 66 | 33 | 13.2 |

## 5. 与 `PARAM.md` 的联动

`f` 从 700 改到 550，以下量需要**按公式重算**（`PARAM.md` 的 R2 关系会自动断言）：

| 参数 | 700 时 | 550 时 | 公式 |
|---|---|---|---|
| 每像素角度 | 0.0818° | **0.1042°** | `180/(πf)` |
| `MASK_DILATE` 的物理宽度 | 0.164° | **0.208°** | `2px × 度/px` |
| `B_MIN`（若 `f_view=f`） | 8.7 mm | **11.1 mm** | `d_min·Z_min/f` |
| `B_MAX` | 279 mm | **354 mm** | `d_max·Z_min/f` |

> 注意：`B_MIN`/`B_MAX` 用的是 `f_view`（视口等效焦距），不是 `f`。
> 若视口保持原图分辨率，则 `f_view = f`，上表成立。

## 6. 配置的加载与校验流程

```
1. 读 json → 校验 schema 版本
2. 展开 "auto" 字段（max_theta 由 f 与 r_corner 算）
3. 逐相机: 构造 NFPose (R_cv, t_cv)  ← SPEC-COORD §2
4. 外参自检 C1–C4                   ← SPEC-COORD §2.3
5. 内参自检: θ_d 单调、max_theta 覆盖图像
6. 交叉校验: PARAM.md §7 的 R1–R6
7. 任一失败 → 返回对应 NF_E_*, 拒绝启动
```

**第 6 步是硬门槛**：`f` 改了但 `B_MIN` 没跟着改，会在这里被抓住。

## 7. 验收

| 编号 | 级别 | 判据 | 负例（必须失败） |
|---|---|---|---|
| V-CAL-1 | L0 | 默认配置下 4 路外参自检 C1–C4 全过 | 把 ML 的 yaw 写成 −90 → 光轴朝内 |
| V-CAL-2 | L0 | `pos_mm` 与车身尺寸自洽（相机在包围盒上） | 写 3000 mm 宽 → 超界 |
| V-CAL-3 | **L0** | **`max_theta` 覆盖 r_corner（128.1°）；若改成 94.5°，四角与左右边缘被误判无效** | **用库默认 1.65 rad → V-CAL-3 失败** |
| V-CAL-4 | L0 | `r_valid=960` 时左右边缘有效、四角无效 | 用 768 → 左右边缘被误判无效 |
| V-CAL-5 | L0 | 改 `f` 后 `PARAM` 的 R2–R5 断言触发 | 只改 f 不改 B_MIN → 断言失败 |
| V-CAL-6 | L0 | `"max_theta":"auto"` 展开值与 (3.1) 一致 | 手填 1.65 → 与公式不符 |

**V-CAL-3 是针对我们已经踩到的真实坑**：`SimpleOCC` 的 `kb_project_points`
默认 `max_theta=1.65`，在这台 f=550 的相机上会静默砍掉左右各 5.5° 的视场。
